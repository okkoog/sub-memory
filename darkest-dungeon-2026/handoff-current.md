# Darkest Dungeon 작업 인수인계 / 서브메모리

기준일: 2026-10-26

## 1. 현재 프로젝트 개요

- 다키스트 던전 1 모드를 대규모로 정리/통합/테스트 중.
- 전체 모드는 약 200개 이상.
- 현재는 전체를 한꺼번에 켜기 전에 **약 20개 단위로 나눠 실행 테스트**하며 오류를 찾는 중.
- 사용자가 진단용으로 올리는 압축파일은 용량 절감을 위해 `heroes` 또는 스킨 텍스처를 의도적으로 뺄 수 있음.
  - 이런 누락은 사용자가 명시한 경우 모드 결함으로 판단하지 말 것.

## 2. 현재 실행 테스트 상태

### 초반 20개
- 게임 실행 및 로딩 성공.
- 플레이 진입은 가능.
- **메인 화면으로 나가기 시 게임이 강제 종료됨.**
- 현재 판정: 조건부 통과.
- 종료 시 크래시는 나중에 전체 조합 테스트에서 다시 확인할 것.

## 3. 지금까지 나온 오류와 원인

### A. mikoF 관련 오류 — 원인 확인됨

표시된 오류 예:
- `Invalid item class in loot table estate-mikoF_Coin`
- `Couldn't read file heroes/mikoF/anim/mikoF.sprite.idle.skel`
- 이후 `BinaryReader::ReadString ... buffer too small!` 오류도 같이 관찰됨.

사용자 확인 결과:
- mikoF 모드는 **먼저 읽혀야 하는 선행/관련 모드가 있었는데 로드 순서를 잘못 배치한 것**이 원인.
- 따라서 mikoF 자체 파일 손상으로 단정하지 말 것.
- 로드 순서 조정 후 상태가 개선됨.

### B. gatekeeper / shard 오류 — 원인 확인됨

표시된 오류:
- `No monster brain class with id:gatekeeper`
- `Invalid item class in loot table shard-`

사용자 확인 결과:
- 게임이 꺼졌다 켜지는 과정에서 DLC가 비활성화되어 있었음.
- DLC를 다시 인식/활성화하자 개선됨.
- 향후 같은 오류가 나오면 우선 DLC 활성 상태를 확인할 것.

### C. Banished 모드 — 현재 미해결 / 조사 보류

문제 화면:

```
Assert Failed:
(pItemClass != nullptr)

Loot::TableEntries::ItemEntry::LoadFromJsonValue
in loot_item_entry.cpp line 41

Invalid item class in loot table
trinket-sels_bh_fire_bombs
```

의심 모드:
- `50_banished.zip`

사용자가 업로드할 때:
- `heroes` 폴더는 용량 관리상 의도적으로 삭제함.
- 따라서 heroes 누락을 원인으로 잡지 말 것.

현재 필요한 조사:
1. `sels_bh_fire_bombs`가 등장하는 loot 정의 파일 찾기.
2. 해당 loot table 내부가 참조하는 item class 확인.
3. 실제 장신구/item 정의와 ID 대조.
4. 선행 모드 누락인지, ID 오타인지, 로드 순서 문제인지 판정.
5. 가능하면 수정본 제작.

현재 상태:
- 파일 자체는 업로드되어 있었으나 당시 실행 도구 오류로 내부 ZIP 분석에 실패.
- 사용자가 **일단 보류** 지시.
- 다음에 재개할 때 가장 먼저 이 항목부터 조사.

## 4. EXE / 대량 모드 패치 상태

사용자가 제공한 파일:
- 최신 게임 원본 EXE 압축: `DarkestEXE.zip`
- 구형 모더 패치:
  `DarkestEXE_Fix_windows_x64_for_Build_26186_v3.0 (暗黑地牢主程序修复补丁64位对应26186版本 by 局外人).7z`

배경:
- 모드가 수십~수백 개가 되면 장신구/리소스 제한 때문에 수정 EXE가 필요.
- 게임 업데이트 후 기존 모더 EXE가 최신 버전과 맞지 않음.

실험:
- 최신 EXE에 구형 패치 기능을 이식한 시험판 `DarkestEXE_2026_실험패치.zip`을 한 차례 제작.
- 이 EXE로 로딩 중 Windows 이벤트 로그:
  - 오류 모듈: `ucrtbase.dll`
  - 예외 코드: `0xc0000409`
- 그러나 사용자가 **순정 최신 EXE에서도 동일하게 크래시**하는 것을 확인함.
- 따라서 당시 크래시는 실험 EXE만의 결함으로 확정할 수 없으며, 대량 모드 구성 문제/제한 문제 가능성이 남아 있음.

주의:
- 이전 분석에서 모더 패치의 내부 기능/설명서를 일부 과도하게 단정한 적이 있으므로,
  **구형 패치의 정확한 기능은 향후 재분석 시 실제 파일을 기준으로 다시 검증할 것.**
- 실험 패치는 실제 게임 정상 작동이 검증된 완성판으로 취급하지 말 것.

## 5. 현재 테스트 전략

- 전체 200+ 모드를 약 20개 단위로 실행 테스트.
- 오류가 뜨면 오류 메시지에 나온 ID를 기준으로 해당 모드를 특정.
- 선행 모드 / 로딩 순서 / DLC 의존성을 먼저 확인.
- 개별 묶음이 실행되면 다음 묶음으로 진행.
- 모든 묶음의 1차 실행 테스트가 끝난 뒤 전체/대규모 조합에서 다시 충돌 여부를 확인할 예정.

오류 분류:
- 실행/로딩 성공 + 종료/메인 복귀 시 크래시 → 조건부 통과로 기록.
- 로딩 중 Assert 및 명확한 ID 오류 → 해당 묶음에서 원인 추적.
- DLC/선행모드/순서 문제로 확인된 것은 모드 자체 불량으로 분류하지 않음.

## 6. 모드 정리/검사 관련 기존 원칙

- 동일 영웅/몬스터의 스켈레톤 호환 여부를 중요하게 봄.
- 스킨 이미지와 `.skel` / `.atlas`가 다른 판본을 무검증으로 섞지 말 것.
- 사용자가 업로드를 위해 텍스처나 `heroes` 폴더를 의도적으로 제거한 경우, 그것을 누락 오류로 보고하지 말 것.
- 모드를 대량으로 다룰 때 단순 폴더명만 보고 판단하지 말고 내부 ID와 설정 참조를 확인할 것.
- 오류는 가능한 한 화면의 정확한 ID/파일 경로/Assert 내용을 기록해서 추적.
