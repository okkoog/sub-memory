# Steam Workshop 업데이트 로그 작성 양식 — 사용자 제공 실제 배포본 기준

대상: Probably Stolen 통합 한국어 번역팩 (`3834117650`).

**2026-11-19 교정**: 이전 문서의 `- ` 고정 하위 항목 규칙과 예시는 사용자가 실제 배포한 형식과 달라 잘못된 양식이었다. 사용자가 직접 제공한 **v0.9.14, v0.9.11, v0.9.10** 원본 로그를 아래에 보존한다. 임의로 예시를 재작성하지 않는다.

## 적용 우선순위

1. 사용자가 이번 작성에 특정 버전·형식·구분을 지정했다면 그 지시를 최우선으로 따른다.
2. 별도 지정이 없다면 **가장 최근 제공된 v0.9.14 배포 로그의 형식**을 기본으로 한다:
   - 첫 줄: `한국어 번역 데이터 업데이트 v{실제 배포 버전}`.
   - 구분 제목: `■ 신규 모드 한국어 지원`, `■ 기존 모드 번역 업데이트`, `■ 작업 결과` 등 **해당하는 구분만** 작성.
   - 모드 이름은 `한국어명 (원제목)`으로 **별도 줄에 배치**, 앞에 하이픈을 붙이지 않는다.
   - 해당 모드의 변경 사항은 **`ㄴ `**으로 시작한다. **`- `로 자동 변경하지 않는다.**
   - `■ 작업 결과` 안의 문장은 하이픈 없이 바로 적는다.
   - 모드 사이와 큰 구분 사이는 빈 줄로 구분한다.
3. **이전 실제 배포 예시 v0.9.11·v0.9.10은 다른 형식**이다. 당시에는 모드 이름 앞에 `- `, 하위 항목에 `└ `, 작업 결과·번역 검수에 `- `를 사용했다. 과거 로그를 다시 작성하거나 사용자가 해당 형식을 지시할 때는 **이 형식을 그대로 유지**한다. 앞뒤 양식을 섞지 않는다.
4. **버전은 추측하지 않는다.** 사용자가 확정한 실제 배포 버전을 쓰고, 미확정이면 `v{버전}`으로 둔다. 과거 배포 로그의 버전을 새 작업에 그대로 사용하는 것도 금지한다. 업데이트 시각도 제공된 경우에만 기재한다.
5. **모드 한국어명은 사용자가 기존 배포에서 쓴 표기**를 우선 재사용한다. 원제목도 모드 원본/기존 배포 기록과 대조하고 임의로 바꾸지 않는다.
6. **신규 번역**, **기존 번역 수정**, **초상화 설정값**, **이미지 참조키**, **단순 검수**를 구분한다. 의미 없는 형식 키를 일반 번역 건수에 합산하지 않는다. 수치·변수 검사 완료 주장도 실제 확인 범위에만 한정한다.
7. 링크, CSV 파일명, GitHub 커밋, ZIP 제작, 내부 배포 과정은 요청이 없으면 업데이트 본문에 넣지 않는다.
8. 사용자가 업데이트 로그를 요청하면 **Steam에 바로 붙여 넣을 본문만** 제공하고 변명·덧붙이는 설명을 넣지 않는다.
