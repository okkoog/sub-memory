# lewd_meme_config

**淫色深空：更多可配置项** —— 面向玩家的全家族数值管理 mod。

- 定位:主 mod `lewd_meme` 与全部家族子 mod(暗流交易 / 巢穴扩展 / 掌上青楼 / tearlaments / 旧版内容 / 清晰立绘 / 物品立绘管理器)数值生态的**最外层调参面板**——谁在场谁拥有语义,本 mod 只把面板值送达正确的载体
- **纯配置 mod,零服务面**:不向任何 mod 提供接口、服务键或事件通道(0.4/0.5 时代的「api」服务已整体移除);也不再有「子模组覆盖」——面板值只有玩家一个来源
- **侵入性最小(穿透原则)**:每个钩子组默认不安装——面板全部开关默认关 = 对应方法**物理上零 hook** = **装上即纯原版**;开启开关即时装上、关闭即时卸载(无需重启;多组共享同一方法时按引用计数卸载,不误伤其他开关)
- 主 mod 闭源成品,本 mod 数值注入只经 `ModReflect.Types("lewd_meme")` 访问;0.8.0 起自检读数额外经前置声明编译引用 `MidnightPawn.dll` 的 `TentacleApi`(1.2.0)公开读接口(仅读取,绝不复制 DLL 进本 mod 目录,数值注入架构不变——API 无数值 setter)
- **与兼容层(lewd_meme_api)二选一**:同装时本 mod 自动让位(不开面板、不装补丁,日志警告)——两 mod 会双重 patch 同一主 mod 方法导致数值叠加。切换需重启游戏
- 前置:`lewd_meme`(**2.1.0**,本版适配基线,精确匹配;TentacleApi 1.2.0);其余 7 个家族子 mod 全部为软依赖(缺席仅警告,对应分区自动消失)
- 能力:**零能力声明**(`<Capabilities />` 为空)

## 数值怎么送达:四类载体

| 载体 | 适用 | 机制 |
|---|---|---|
| 主 mod 方法接管 | 默认(主 mod 全部参数) | Harmony prefix/postfix 复刻主 mod 方法,写死常量换成配置读 |
| 子 mod 配置写透 | 暗流交易 8 键 / 巢穴扩展 12 键(对方有官方配置键) | **零 hook**——直接写对方 ModConfig,最抗对方更新 |
| 子 mod 方法接管 | 掌上青楼 22 键 / tearlaments 6 键(对方数值 const 内联、无配置系统) | patch 对方方法(声明前置 → ModReflect 合法) |
| 让位 | 语义所有者是在场子 mod 且无诚实映射 | 不 hook、不写,面板行注明「××在场,由此让位」 |

**让位(Router 装配期裁决,9 个让位单元)**:暗流交易在场时,掉落节流、排卵针价格两单元让位(其 1.6.1 起为插入式共存 transpiler、不再改写方法体——夜间数值面、产女、闹钟、陷阱等其余单元恢复本 mod 接管);巢穴扩展在场时,夜间乳汁单价、乳汁价格两单元、精液三值等 4 个单元让位(1 独有 + 3 共享;主 mod 1.9.2 已删经验表静态数组,经验公式三键恒 Own、不再让位);物品立绘管理器在场时,少女生成两单元与阵营/体型/胸部三池让位(其工厂挂钩链替换池抽取、全程接管原方法,保证高清立绘不回退;职业池零替换恒 Own)。暗流交易自己的参数由「暗流交易联动」分区承担,巢穴扩展同理由「巢穴扩展联动」承担。

**每键开关(默认全关 = 装上即纯原版)**:

- 每个数值/CSV 配置键前有一条「启用:×××」开关:关闭 = 该键用原版默认
- 开关只压**玩家面板层**;主 mod 官方面板的键(拾荒分区等)经「主 mod 官方设置」写透分区镜像,双面板并存
- 开关即物理装卸:开 = 该钩子组装上(未开启的键在补丁内读默认值 = 原版行为),关 = 该钩子组卸载;池类配置(体型/职业/阵营/胸部池)关闭时**立即回滚**原版分布(不用重启)

> 总开关/分区开关已移除:游戏 mod 配置面板是「应用」模型(控件互相独立,程序化改其他开关的值无法刷新正在显示的控件),层级联动在 UI 层无法实现。

**入口**:主菜单 →「模组」菜单 → 本模组条目的**齿轮按钮**。面板由游戏自动生成。局中(开店时)没有配置界面——主菜单改值 → 应用 → 进游戏后即时生效。

**精确文本输入**:全部数值键的行内是文本框(滑条只作粗调,游戏滑槽显示的数值不准确)。输入自动 Trim、非法输入(如 `7O`)保持当前生效值并日志一次;越界钳制:概率键钳到 [0,1],其余数值键下限保留(非负防呆)、上限宽松(999999/999)——**不遵循主 mod / 子 mod 的原面板上限**。CSV 键格式不变。

**写透键的双面板语义**(暗流交易联动 / 巢穴扩展联动):开启 = 把本面板值写入对方官方配置并立即生效(**双面板并存**:对方面板同步显示同一存储);关闭 = **恢复开启时刻的快照**(开启时记录对方当前值;关闭即写回,不动你自己在对方面板设的值)。并发是**被动后写优先**:启用期间以本面板为准(我方写入立即生效);期间你在对方面板的修改以对方为准,直到本面板下一次改动——本 mod 从不订阅对方变更、不会把对方面板的编辑当场弹回。快照仅会话内存,重启后首次开启重新锚定;镜像初值不强行同步对方已有非默认值(以本面板存储为准,tooltip 已注明)。

**持久化**:`<persistentDataPath>/ModConfigs/lewd_meme_config.json`,跨存档槽共用;写透键的值同时落在对方自己的 ModConfigs json 里。

**取值链**(当前生效值从上往下取第一个命中的层):

```
[开关检查:该键「启用」开关关 → 跳过玩家层]
  > 玩家面板值(≠默认 且 开关开)
  > 默认值(= 主 mod v2.1.0 / tearl 15 原版字面量,2.1.0 复核;0.8.0 起原
    「主模组面板动态层」随拾荒概率键退役撤销——官方面板值经「主 mod 官方
    设置(拾荒)」写透分区直达官方配置,不经取值链)
```

**不上面板的键**:9 个布局尺寸键(`layout.*` 5 键、闹钟/陷阱的 `brood_size` / `output_size`)——玩家误改会破坏主 mod 布局逻辑,仍只作为注册表键由对应钩子组消费。

### CSV 键格式(文本框)

逗号分隔,自动去除每项两侧空格:

- **区间**:`"70,80"`(下,上)
- **列表/池**:`"贫乳,普乳,巨乳"`
- **键值**:`"上层区:100,治安部:50,其他:10"`(阵营基价,「其他」= 未命中兜底)
- **数值组**:`"0.1,0.2,0.3"`(策略捕捉率,恰 3 项)

**容错**:非法输入(如 `"7O,8O"`)不会炸面板或装配——数值区间/基价表整串回退默认值并日志警告(每键每会话一次),列表类跳过空项;策略捕捉率整串回退主 mod 数组现值。

### 等级上限 ↔ 经验公式(0.7.0)

主 mod 1.9.2 把逐级经验表改为公式 `基础值 + 每档增量 × (等级 ÷ 每 N 级一档)`,本面板以**经验公式三键**(基础值 / 每 N 级一档 / 每档增量)接管,默认 100/3/100 = 原版逐字。`等级上限` 默认 5(原版),1.9.2 起升级循环本身无上限条件——等级可以超过「等级上限」继续涨(经验照常累积),上限只在**读取路径**生效(显示与消费侧按 cap 封顶)。想要高等级养成:调高 `等级上限` 即可,经验曲线另调三键。

### 自定义名字库迁移

启用「启用自定义名字库」后读取 `ModData/lewd_meme_config/names_custom.txt`。**从兼容层(lewd_meme_api)切换过来且用过自定义名字库的玩家**:手动把 `ModData/lewd_meme_api/names_custom.txt` 复制到 `ModData/lewd_meme_config/`,否则回退原版名字库并日志警告(不做自动迁移)。

## 游戏内调试面板(开发/验收用,发布版关闭)

- 发布版**编译期关闭**:开关是源码常量——`Source/Integration/DebugPanel.cs` 的 `internal const bool Enabled = false`。false 时零 GameObject、零 F9 注册、零事件订阅,面板代码完全不可达。需要时把它改成 `true` 重新编译即可。
- 启用后进入存档,按 **`[`** 键呼出/收起;也可 F9 开发菜单 → 本 mod → Special →「调试面板」。
- 三区:
  1. **状态总览**:8 个家族 mod 的在场 × 版本 × 路由裁决 + 全部装配单元的期望态 vs 实际态(偏差行标红)
  2. **自检**(共 269 项,逐项 PASS/FAIL/SKIP,结果同步 Player.log):路由审计(75 个可装配单元)/ 值生效直测(确定性纯静态直调 + 物品工厂直测)/ 写透往返(开启 → 对方值断言 → 关闭恢复)/ 读路径兜底(开关与装配态核对;写透单元不设审计行——其真自检由写透往返承担)
  3. **写透快照**:每镜像键的快照持有状态与对方当前值
- 自检的「临时写并复原」只发生在自检执行器内部,不改变任何装配/路由语义。

## 构建

需要 .NET SDK 与正版游戏。在模组根目录(git bash)执行:所有编译输出重定向到 `%TEMP%\ProbablyStolenLewdMemeConfig\`,最后只把 manifest 已声明的 `LewdMemeConfig.dll` 复制回模组根目录:

```bash
set -e
build_root="$(cygpath -m "$TEMP")/ProbablyStolenLewdMemeConfig"
managed_path="$(cygpath -m '../../Probably Stolen_Data/Managed')"
dotnet build ./Source/LewdMemeConfig.csproj -c Release \
  "-p:GameManaged=$managed_path" \
  "-p:BaseIntermediateOutputPath=$build_root/mod-obj/" \
  "-p:OutputPath=$build_root/mod-bin/"
dotnet build ./Source/Tests/Tests.csproj -c Release \
  "-p:GameManaged=$managed_path" \
  "-p:BaseIntermediateOutputPath=$build_root/test-obj/" \
  "-p:OutputPath=$build_root/test-bin/"
dotnet "$build_root/test-bin/Tests.dll"
cp "$build_root/mod-bin/LewdMemeConfig.dll" ./LewdMemeConfig.dll
```

游戏安装在其它位置时,把 `managed_path` 改成该游戏 `Probably Stolen_Data\Managed` 的绝对路径(保持 `C:/...` 正斜杠形式,MSBuild 才能识别)。**在 `.worktrees/` 下构建时**相对路径多出两层,直接用绝对路径覆盖 `-p:GameManaged` 最稳。

⚠️ 不要把 bin/obj、多余 DLL 或构建脚本放回模组目录——游戏扫描整个模组文件夹,任何未在 manifest `Assemblies` 声明的 DLL 都会导致激活被拒。构建命令也不要另存为模组目录内的 .sh/.bat/.ps1。
