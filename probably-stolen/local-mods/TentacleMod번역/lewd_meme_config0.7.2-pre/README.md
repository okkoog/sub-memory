# lewd_meme_config

**음란한 심우주: 더 많은 설정 항목** — 플레이어가 모드 가족 전체의 수치를 조절하는 관리 모드입니다.

- **역할:** 본편 `lewd_meme` 및 확장 모드(암류 거래 / 촉수 둥지 확장 / 손안의 유곽 / tearlaments / 구형 콘텐츠 / 선명한 초상화 / 아이템 초상화 관리자)의 수치 설정을 제어하는 **가장 바깥쪽 설정 패널**입니다. 실제 기능과 데이터의 의미는 각각의 모드가 담당하며, 이 모드는 플레이어가 입력한 수치를 알맞은 담당 모드로 전달합니다.
- **설정 전용, 서비스 제공 없음:** 다른 모드에 API, 서비스 키 또는 이벤트 통로를 제공하지 않습니다. 0.4~0.5 버전의 `api` 서비스는 모두 제거했습니다. '하위 모드의 설정 덮어쓰기'도 없으며, 패널 값의 원천은 플레이어 한 곳뿐입니다.
- **최소한의 개입(투과 원칙):** 모든 패치 그룹은 기본적으로 설치되지 않습니다. 전부 꺼짐 = 해당 메서드의 **실제 Hook 0개** = 설치 직후 원본 모드와 같은 상태입니다. 스위치를 켜면 즉시 설치하고 끄면 즉시 해제하므로 재시작할 필요가 없습니다. 여러 그룹이 같은 메서드를 공유하면 참조 횟수에 따라 해제해 다른 활성 옵션을 망가뜨리지 않습니다.
- 본편은 소스가 없는 배포 DLL이므로 `ModReflect.Types("lewd_meme")`를 통해서만 접근하며, 본편 DLL을 직접 컴파일 참조하지 않습니다.
- **호환 계층 `lewd_meme_api`와 택일:** 둘 다 설치하면 이 모드가 자동으로 양보하여 패널을 열거나 패치를 설치하지 않고 로그에 경고를 기록합니다. 두 모드가 같은 본편 메서드를 이중 패치해 수치가 중복 적용되는 일을 막기 위함입니다. 둘 사이를 전환하려면 게임을 재시작해야 합니다.
- 필수 선행 모드: `lewd_meme` **1.9.2**(이 버전의 정확한 호환 기준). 나머지 7개 확장 모드는 선택 사항입니다. 설치되지 않으면 경고만 표시하고 해당 설정 구역을 숨깁니다.
- **별도의 권한 선언 없음:** `<Capabilities />`가 비어 있습니다.

## 값이 전달되는 네 가지 방식

| 처리 방식 | 적용 대상 | 작동 방법 |
| --- | --- | --- |
| 본편 메서드 제어 | 기본적으로 본편의 모든 조절 항목 | Harmony prefix/postfix가 원본 메서드 동작을 재현하면서 고정 수치를 설정값 조회로 바꿉니다. |
| 확장 모드 설정값 직접 기록 | 암류 거래 8키 / 촉수 둥지 확장 12키(공식 설정 키가 존재) | **Hook 0개**. 상대 모드의 `ModConfig`에 직접 값을 쓰므로 상대가 업데이트돼도 상대적으로 안정적입니다. |
| 확장 모드 메서드 제어 | 손안의 유곽 22키 / tearlaments 6키(상대가 상수로 수치를 코드에 내장하고 설정 시스템 없음) | 허용된 선행 모드의 해당 메서드를 패치합니다(`ModReflect` 사용). |
| 양보 | 해당 수치의 실제 의미를 소유한 확장 모드가 설치돼 있고 안전한 연동 방식이 없음 | Hook도 설치하지 않고 값도 쓰지 않습니다. 설정 행에 'XX 모드가 있어 이 항목은 양보함'을 표시합니다. |

**양보 판정(라우터 초기 조립 시 9개 항목):** 암류 거래가 활성화되면 드롭 빈도 제한과 배란 유도제 가격 2개 항목을 양보합니다(1.6.1부터 부분 삽입형 transpiler로 공존하며 메서드 본문을 통째로 대체하지 않으므로, 야간 수치·딸 생성·알람시계·함정 등 다른 항목은 이 모드가 다시 제어합니다). 촉수 둥지 확장이 활성화되면 야간 모유 단가, 모유 가격 2개 항목, 정액 수치 3개 등 총 4개 항목을 양보합니다(전용 1개 + 공유 3개). 본편 1.9.2에서는 경험치 표의 정적 배열이 삭제돼 경험치 공식 세 키는 항상 이 모드가 제어합니다. 아이템 초상화 관리자가 있으면 캐릭터 생성 2항목과 세력·체형·가슴 크기 생성 풀 3항목을 양보합니다. 해당 모드의 생성기 Hook 체인이 목록 추출을 완전히 대신하고 원래 메서드까지 제어하기 때문에 고해상도 초상화가 원래 이미지로 돌아가지 않도록 합니다. 직업 풀에는 이와 같은 교체가 없어서 항상 이 모드가 관리합니다. 암류 거래 자체의 매개변수는 '암류 거래 연동' 설정에서, 촉수 둥지 확장의 매개변수는 '촉수 둥지 확장 연동'에서 조절합니다.

## 정확한 버전 종속

이 빌드는 아래 **8개 모드의 지정 버전**을 각각 확인하고 연결하도록 작성됐습니다.

| 모드 | 지정 버전 |
| --- | --- |
| 음란한 심우주 `lewd_meme` | 1.9.2 |
| 암류 거래 `lewd_meme_remake` | 1.6.4 |
| 촉수 둥지 확장 `claude.lewdMemeBrood` | 0.3.31 |
| 손안의 유곽 `lewd_meme_brothel` | 0.10.4 |
| tearlaments `dui_mian_lan_qiu_ji_tearl` | 7 |
| 구형 콘텐츠 `lewd_meme_legacy_content` | 1.0.6 |
| 선명한 초상화 `lewd_meme_crisp_portraits` | 1.0.0 |
| 아이템 초상화 관리자 `item_portrait_hd` | 1.2.18 |

대상 모드가 활성화됐으나 **버전이 일치하지 않으면** 해당 모드의 Hook 기반 항목을 실행 중 자동으로 비활성화합니다. 이는 모든 관련 스위치를 끈 것과 같아 미설치 Hook은 설치되지 않고 이미 설치된 Hook은 해제됩니다. 패널의 값과 스위치 양쪽 행에 **'***버전 불일치, 이 항목은 적용되지 않음'**이라는 문구를 추가합니다. 설정 JSON을 수정하지 않으므로 플레이어가 입력한 값은 그대로 남으며, 향후 지정 버전을 갱신하면 자동으로 다시 적용됩니다. 상대 모드의 공식 설정 키를 직접 쓰는 항목은 이 버전 제한의 영향을 받지 않습니다. 실제로 존재하는 설정 키를 이용하므로 상대 모드 업데이트에 비교적 강합니다.


> **원문 버전 표기 차이:** 원본 README의 연동 표는 `item_portrait_hd`를 **1.2.18**로 기재하지만, 동일 버전 원본 `manifest.xml`의 소개문에는 **1.3.0**이라고 적혀 있습니다. 두 값은 제작자의 원문에서부터 불일치합니다. 실제 Hook 버전 제한은 DLL 구현에 의해 결정되므로 이 번역에서 어느 쪽이 맞다고 임의로 단정하거나 ID/버전을 변경하지 않았습니다.

연동 구역에서는 **'사용' 스위치가 먼저, 값 입력이 나중**에 배치됩니다. 암류 거래의 차이 항목과 공식 설정 직접 기록 항목이 같은 구역에 섞여 있지만 모두 각자의 스위치로 제어합니다. 암류 거래가 활성화되면 본편 쪽 드롭 빈도 제한과 배란 유도제 가격은 양보하며, **'암류 거래 활성화: 이 설정은 적용되지 않음'**이라는 녹색 작은 글씨를 표시합니다. 암류 거래 자체의 추가 매개변수는 이 구역의 메서드 제어 항목에서 관리합니다.

드롭 구역의 **'의료팀 배란 유도제 드롭 복원'** 두 키는 사용자가 직접 켜야 적용됩니다. 본편 1.7.0부터 의료팀의 배란 유도제 드롭 분기가 삭제됐으며 1.9.2에도 없습니다. 기본적으로 두 스위치를 끄면 1.9.2와 같은 동작입니다. 어느 하나라도 켜면 예전 1.6.x의 의료팀 판정 분기를 되살리고 확률 및 키워드는 패널 값으로 읽습니다.

### 개별 키 스위치(기본 모두 꺼짐)

- 각 수치/CSV 설정 앞에는 '사용: XXX' 스위치가 있습니다. 끄면 해당 설정에 원본 기본값을 사용합니다.
- 스위치는 **사용자 설정 패널 층**에만 적용됩니다. 본편 자체 패널에서 설정한 폐품 수집 중 캐릭터 발견 확률은 여기 스위치의 영향을 받지 않습니다.
- 스위치가 곧 실제 Hook 설치·제거를 제어합니다. 켜면 해당 그룹을 설치하고, 그룹 안에서 꺼진 설정은 패치 중 원본 기본값을 읽도록 합니다. 끄면 그룹을 해제합니다. 체형·직업·세력·가슴 크기 생성 풀 관련 스위치를 끄면 **즉시 원본 분포로 돌아가며 재시작이 필요하지 않습니다.**

전체 스위치와 구역별 스위치는 제거됐습니다. 게임의 모드 설정 패널은 **'적용' 방식**으로 작동합니다. 각 컨트롤이 독립적이므로 코드로 다른 컨트롤의 값을 바꾸더라도 현재 보이는 화면을 다시 그리지 못합니다. 따라서 계층 구조의 연동을 UI에서 안정적으로 구현할 수 없습니다.

**진입 경로:** 메인 메뉴 → '모드' → 이 모드 항목의 **톱니바퀴 버튼**. 게임이 자동 생성한 패널이며 상점 운영 중에는 설정 화면을 열 수 없습니다. 메인 메뉴에서 값 변경 → 적용 → 게임에 들어가면 바로 적용됩니다.

**정확한 숫자 입력:** 모든 숫자 설정 행에는 텍스트 상자가 있습니다. 슬라이더는 대략적인 조정용으로만 사용하세요. 게임 슬라이더에 표시되는 숫자가 정확하지 않습니다. 입력값은 앞뒤 공백을 자동으로 제거합니다. `7O`처럼 잘못된 문자는 현재 적용 중인 값을 유지하고 로그를 한 번 남깁니다. 확률값은 `[0,1]`로 제한하고 다른 숫자는 음수를 막는 하한을 유지하되 상한은 비교적 넉넉한 `999999/999`를 적용합니다. **본편이나 확장 모드의 원래 패널 상한을 따르지 않습니다.** CSV의 입력 형식은 변경하지 않습니다.

**공식 설정 직접 기록 키의 두 패널 동작**(암류 거래·촉수 둥지 확장): 이 모드에서 스위치를 켜면 설정값을 해당 모드의 공식 설정에 기록하고 즉시 적용합니다. 두 패널은 같은 저장값을 표시합니다. 스위치를 끄면 **스위치를 켰던 시점의 값으로 복원**합니다(켜는 순간 상대의 현재 값을 저장하고 끄면 다시 씁니다. 상대 모드 패널에 입력해 둔 값을 영구적으로 변경하는 기능이 아닙니다). 동시에 변경하면 **마지막으로 기록한 값이 우선**하는 소극적 규칙을 따릅니다. 스위치를 켠 뒤 이 패널의 값을 바꾸면 즉시 적용되지만, 상대 모드 패널에서 직접 고친 값은 이 패널에서 다음 수정을 하기 전까지 유지됩니다. 상대 설정의 변경 이벤트를 구독하거나 상대 편집을 즉시 되돌리지 않습니다. 복원용 스냅샷은 현재 게임 세션의 메모리에만 있으며 재시작 후 다시 처음 켜면 당시 값을 새 기준으로 잡습니다. 상대 패널의 기존 비기본값을 초기 표시값으로 강제 동기화하지는 않고 이 패널의 저장값을 사용합니다. 이 점은 툴팁에도 표시돼 있습니다.

**설정 저장 위치:** `<persistentDataPath>/ModConfigs/lewd_meme_config.json`. 모든 저장 슬롯에 공통으로 사용합니다. 공식 설정 직접 기록 값은 상대 모드의 `ModConfigs` JSON에도 저장됩니다.

**현재 적용되는 값의 우선순위**(위에서 아래 순서로 먼저 조건에 맞는 값 사용):

```
[스위치 확인: 해당 값의 '사용' 스위치가 꺼짐 → 플레이어 입력층 건너뜀]
  > 플레이어 패널의 값(기본값과 다르고 스위치가 켜진 경우)
  > 본편 설정 패널의 동적 값(폐품 수집 중 캐릭터 발견 확률만 해당:
    본편 maiden_loot_chance; 이 모드의 스위치로 제한하지 않음)
  > 기본값(본편 lewd_meme v1.9.2의 원래 코드값과 동일, 1.9.2에서 재확인)
```

**패널에서 숨긴 키:** 총 9개의 배치 크기 키(`layout.*` 5키와 알람시계·함정의 `brood_size`, `output_size`). 플레이어가 임의로 바꾸면 본편의 화면 배치를 망가뜨릴 수 있으므로 화면에 노출하지 않고 해당 패치 그룹이 참조하는 등록 키로만 사용합니다.

### CSV 입력 키 형식

쉼표로 항목을 나누며 각 항목 앞뒤의 공백을 자동으로 제거합니다.

- **범위:** `70,80`(최솟값, 최댓값)
- **목록/풀:** `贫乳,普乳,巨乳`(각 항목은 게임이 사용하는 원문 값)
- **키:값:** `上层区:100,治安部:50,其他:10`(세력 기본 가격, `其他`는 일치 항목이 없을 때 적용)
- **숫자 3개:** `0.1,0.2,0.3`(전략별 포획 확률, 정확히 3개)

**오류 허용:** `7O,8O`처럼 입력해도 설정 화면이나 Hook 설치가 중단되지 않습니다. 숫자 범위나 세력 기본 가격은 문자열 전체를 기본값으로 돌리고 키별·게임 세션별로 경고를 한 번만 남깁니다. 목록 입력에서는 빈 항목을 건너뜁니다. 전략별 포획 확률이 잘못되면 본편의 현재 배열값으로 되돌립니다.

### 레벨 상한과 경험치 공식 (0.7.0)

본편 1.9.2는 레벨별 경험치 표를 `기본값 + 단계별 증가량 × (레벨 ÷ 단계당 N레벨)` 공식으로 변경했습니다. 이 패널은 경험치 공식 3키(기본값 / 몇 레벨당 한 단계 / 단계별 증가량)를 제어합니다. 기본값 **100/3/100**은 본편 코드와 정확히 같습니다.

'레벨 상한'의 기본값은 본편과 같이 **5**입니다. 다만 1.9.2부터 레벨 업 반복문 자체에는 상한 조건이 없어 설정 상한을 넘어도 레벨 및 경험치는 계속 쌓입니다. 상한은 **조회 경로**에서만 적용됩니다. 즉 화면 표시 및 소비 기능에서 제한값까지만 읽습니다. 더 높은 레벨을 키우고 싶다면 '레벨 상한'을 올리고, 경험치 증가 곡선은 별도의 3키로 조정하세요.

### 사용자 이름 목록 이전

'사용자 지정 이름 목록' 옵션을 켜면 `ModData/lewd_meme_config/names_custom.txt`를 읽습니다. 이전 호환 계층 `lewd_meme_api`에서 사용자 이름 목록을 사용하다가 이 모드로 바꾼 경우, 기존 `ModData/lewd_meme_api/names_custom.txt`를 수동으로 `ModData/lewd_meme_config/`로 복사해야 합니다. 그러지 않으면 기본 이름 목록으로 돌아가고 경고 로그를 남깁니다. 자동 이전 기능은 없습니다.

## 게임 내 디버그 패널(개발·검증용, 배포판에서 꺼짐)

- 배포판에서는 **컴파일 시점에 비활성화**돼 있습니다. 소스 `Source/Integration/DebugPanel.cs`의 `internal const bool Enabled = false`가 제어합니다. `false`일 때 생성되는 GameObject, 등록되는 F9 메뉴, 구독되는 이벤트는 모두 0개이며 패널 코드는 실행할 수 없습니다. 필요할 때 `true`로 바꾼 뒤 다시 컴파일하면 됩니다.
- 켠 다음 저장 파일에 들어가 **`[`** 키로 열고 닫습니다. F9 개발 메뉴 → 이 모드 → Special → '디버그 패널'에서도 실행할 수 있습니다.
- 세 개의 구역:
  1. **상태 개요:** 가족 모드 8개의 설치 상태 × 버전 × 라우터 선택과 모든 Hook 단위의 예상 상태/실제 상태를 보여 줍니다. 불일치 행은 빨간색으로 표시합니다.
  2. **자체 검사:** 총 **269개** 항목을 PASS/FAIL/SKIP로 검사하고 결과를 `Player.log`에도 저장합니다. 라우터 감사(설치 가능한 항목 75개), 실제 값 반영 검사(결정적인 정적 직접 호출 및 아이템 생성기 직접 시험), 직접 기록 값 왕복(켜기 → 상대 값 검증 → 끄고 원래 값으로 복원), 값 조회 경로의 대체 동작 검사를 포함합니다. 직접 기록 항목에는 별도의 감사 행을 추가하지 않으며 실제 검증은 왕복 검사로 수행합니다.
  3. **직접 기록 스냅샷:** 복제 기록 키별로 현재 복원 스냅샷의 보유 여부와 상대 모드의 현재 값을 표시합니다.
- 자체 검사의 '임시 기록 후 복원'은 검사 실행기 내부에서만 실행되고 실제 Hook 설치나 라우터의 선택 규칙을 바꾸지 않습니다.

## 12월 10일 보안 업데이트와 가족 모드 유지 여부

- `threads`, `reflection-external`, `native`, `dynamic-code`의 네 권한은 12월 10일부터 직접 로딩을 거절하도록 예정돼 있습니다. 가족 모드 중 아직 거절 대상에 해당하는 것은 **선명한 초상화(`crisp_portraits`)와 손안의 유곽(`brothel`)** 두 개뿐입니다. 비활성화되면 이 모드에서도 관련 연동 구역이 자연스럽게 사라집니다(선행 모드가 없다는 경고만 표시).
- **구형 콘텐츠(`legacy_content`) v1.0.5는 `ModReflect`로 이전**했으므로 더 이상 거절 대상이 아닙니다.
- 이 모드 자체에는 선언된 권한이 없으며, `mod-scan`에도 HardFlags, DeprecatedCapabilities, Pending 표시가 없습니다.

## 빌드

.NET SDK와 정식 게임이 필요합니다. 모드 루트 폴더에서 Git Bash로 실행합니다. 모든 컴파일 결과물은 `%TEMP%\ProbablyStolenLewdMemeConfig\`로 출력한 뒤, manifest에 지정된 `LewdMemeConfig.dll`만 모드 루트에 복사합니다.

```bash
set -e
build_root="$(cygpath -m "$TEMP")/ProbablyStolenLewdMemeConfig"
managed_path="$(cygpath -m '../../Probably Stolen_Data/Managed')"
dotnet build ./Source/LewdMemeConfig.csproj -c Release \
  "-p:GameManaged=$managed_path" \
  "-p:BaseIntermediateOutputPath=$build_root/mod-obj/" \
  "-p:OutputPath=$build_root/mod-bin/"
dotnet build ./Source/Tests/Tests.csproj -c Release \
  "-p:GameManaged=$managed_path" \
  "-p:BaseIntermediateOutputPath=$build_root/test-obj/" \
  "-p:OutputPath=$build_root/test-bin/"
dotnet "$build_root/test-bin/Tests.dll"
cp "$build_root/mod-bin/LewdMemeConfig.dll" ./LewdMemeConfig.dll
```

게임 설치 위치가 다르면 `managed_path`를 `Probably Stolen_Data\Managed`의 절대 경로로 변경하세요. MSBuild가 인식할 수 있도록 `C:/...`처럼 슬래시를 사용합니다. `.worktrees/`에서 빌드하면 상대 경로가 두 단계 더 깊어지므로 `-p:GameManaged`에 절대 경로를 주는 것이 가장 안정적입니다.

**주의:** `bin/obj`, 불필요한 DLL 또는 빌드 스크립트를 모드 폴더에 넣지 마세요. 게임은 모드 폴더 전체를 검사하므로 manifest의 `Assemblies`에 등록되지 않은 DLL이 하나라도 있으면 활성화가 거부될 수 있습니다. 빌드 명령을 모드 폴더의 `.sh`, `.bat`, `.ps1` 파일에 별도로 저장하지도 마세요.

## 검증

- 게임 실행 파일 옆에 빈 `dev.txt`를 놓으면 F8 콘솔과 F9 개발 메뉴를 사용할 수 있습니다. `Mods` 메뉴의 Developer mode를 켜면 로컬에서 다시 빌드한 DLL을 신뢰하도록 할 수 있습니다.
- F8 명령: `mod-scan lewd_meme_config`(스캐너 검색 및 코드 지문), `mod-reflect`(거부된 ModReflect 조회).
- 목표: 별도 권한을 선언하지 않은 상태에서 `mod-scan`의 HardFlags / DeprecatedCapabilities / Pending이 모두 없어야 합니다(암류 거래 확장과 비교 가능).
- 중요 기준: 이 모드만 설치하고 모든 스위치가 기본 꺼짐이면 **실제 패치 0개**여야 합니다. F8 `mod-reflect`로 확인할 수 있습니다.
- 버전 검사: 가족 모드 버전과 지정 버전이 다르면 관련 설정 행에 '***버전 불일치, 이 항목은 적용되지 않음'이 나타나고, 해당 모드는 Hook을 설치하지 않으며 저장된 스위치 설정값은 보존돼야 합니다.
