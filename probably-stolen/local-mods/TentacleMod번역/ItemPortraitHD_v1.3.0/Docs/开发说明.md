# 개발 안내

## 빌드와 검증

**.NET 8 SDK**를 사용합니다. 프로젝트는 로컬 게임의 Managed 어셈블리를 직접 참조합니다. 게임 경로가 달라졌다면 `-p:GameManaged=전체경로`로 지정합니다.

모드 루트 폴더에서 PowerShell을 실행하고, 실제 설치된 DLL을 덮어쓰지 않도록 결과물을 임시 폴더에 출력하세요.

```powershell
$sourceRoot = Join-Path (Get-Location) 'Source'
$buildRoot = Join-Path $env:TEMP 'ItemPortraitHD-validation'
dotnet build "$sourceRoot/ItemPortraitHD.csproj" -c Release --configfile "$sourceRoot/NuGet.Config" "-p:BaseIntermediateOutputPath=$buildRoot/mod-obj/" "-p:OutputPath=$buildRoot/mod-bin/"
dotnet build "$sourceRoot/Tests/Tests.csproj" -c Release --configfile "$sourceRoot/NuGet.Config" "-p:PortraitAssembly=$buildRoot/mod-bin/ItemPortraitHD.dll" "-p:BaseIntermediateOutputPath=$buildRoot/test-obj/" "-p:OutputPath=$buildRoot/test-bin/" -p:UseAppHost=false
$env:MONOMOD_DMD_TYPE = 'cecil'
$originalDll = '원본 모드 MidnightPawn.dll의 전체 경로'
$scanFolder = Join-Path $buildRoot 'scan'
New-Item -ItemType Directory -Force -Path $scanFolder | Out-Null
Copy-Item -LiteralPath "$buildRoot/mod-bin/ItemPortraitHD.dll", './manifest.xml' -Destination $scanFolder
dotnet "$buildRoot/test-bin/Tests.dll" $originalDll $scanFolder
```

빌드 또는 테스트 명령 하나가 성공한 후에 다음 단계로 진행합니다. 회귀 검사의 공통 진입점은 **원본 모드 DLL**과 **검사 대상 폴더**를 두 개의 인수로 받습니다. 두 번째 인수로 넘긴 폴더의 DLL을 검사하므로 방금 빌드한 후보 결과물을 사용해야 합니다.

후킹 메서드 서명과 IL 전환 검사, 이름 보호, 기본 이미지 및 가중치 규칙, 보관함 순회, 캐시 등록 항목 갱신 검사를 유지합니다. 특정 이미지 출처 팩의 버전에 종속된 스냅샷, 중복 알고리즘 비교, 전용 명령 진입점은 제거했습니다. 순수 .NET 테스트에서는 Unity의 네이티브 텍스처를 할당하지 않습니다. IL 명령 검사는 호출 관계만 증명할 뿐, 화면 표시나 리소스 폐기 동작까지 검증하는 것은 아닙니다.

## 유지보수 규칙

초상화 팩별 전용 연동 코드는 `Source/Integrations`에 둡니다. AllGirls, Rimworld, 백사 리소스 및 각 팩의 매핑 파싱 등이 해당합니다. 해당 폴더 밖에는 공통 이미지 선택, 변환 캐시, 기본 `lewd_meme` 호환 진입점을 유지합니다. 새 이미지 팩용 연동 코드도 이 폴더에 추가합니다.

- 원본 소스 코드를 기준으로 체형 목록, CSV 위치 인덱스, 이미지 출처 설정, 기존 값 이전 기능을 유지합니다. 구형 DLL 목록을 근거로 항목을 임의로 보충하지 않습니다.
- 세 이미지 선택 전략은 선택 범위와 가중치 의미가 다릅니다. 스캔, 표본 표와 변환 캐시를 공유할 수는 있지만 각 전략의 경로와 저장되는 출처 ID는 유지합니다.
- 게임이 공개한 속성과 `Sprite` 사전은 직접 접근합니다. 원본 캐릭터의 경계는 직렬화된 `SpriteEntry` 목록을 기준으로 하며, 실행 중 추가된 별칭까지 포함하는 전체 사전으로 대신해서는 안 됩니다.
- 게임의 `ModLoader`가 이미 이 어셈블리에 패치를 적용하므로, 진입점에서 `PatchAll`을 중복 호출하지 않습니다. 외부 모드 타입은 접근 권한 선언에 따라 `ModAccess` 또는 `ModReflect`로 읽습니다.
- 단축키는 `AddGameOptionKeyBind`를 이용하고, 관리자의 입력은 `KeyBindHelper.SuppressHotkeys`를 따릅니다. 독립된 키 재설정 이벤트 처리 루프를 다시 만들지 않습니다.
- 가중치 표는 캐릭터, 출처 또는 가중치 버전이 달라질 때 무효화합니다. 최종 이미지 스캔의 변화만으로 관계없는 로컬 PNG 풀을 다시 생성하지 않습니다.
- 출력 `Sprite`/`Texture`의 소유자는 `Portraits`로 통일합니다. 변환 결과가 무효화되더라도 외부에서 사용 중인 객체는 먼저 유지하고, 재구성할 때 이전 결과를 참조하는 등록 키만 갱신한 다음 참조가 남지 않은 객체를 회수합니다.
- 출력 텍스처는 **CPU에서 읽을 수 있어야 합니다.** 게임의 `SetSpriteAndShapeFromMod`가 픽셀을 읽기 때문입니다. 기존의 투명 영역 자르기, 종횡비를 유지하는 캔버스, 미리 곱해진 알파의 샘플링을 유지하며 일반적인 `Blit`이 똑같이 동작한다고 가정하지 않습니다.
- PNG 디코딩은 Unity에 맡기지만 디코딩 전에는 형식과 **32MB/4096픽셀** 제한을 검사합니다. 이미지 가져오기 경로, 해시 기준 중복 제거, 원자적 파일 저장을 중복 코드 정리 과정에서 삭제해서는 안 됩니다.

## 게임 내 확인 항목

세 가지 모드별 새 캐릭터 생성, 고객 표시, F7 수동 교체와 복원, 출처 팩 다시 불러오기, 128↔256 전환, 모드 비활성화 후 재활성화, 저장 파일 왕복, 구형 아이템의 공간 부족 시 원상복구 등을 확인합니다. 단축키 변경 과정에서는 Esc 취소와 키 변경 프레임에서 관리자가 열리거나 닫히지 않는지도 확인합니다.

설치본을 수정하기 전에는 게임을 종료하세요. 검사 대상 DLL을 덮어쓴 뒤 다시 시작합니다. 소스 빌드가 성공했다고 현재 설치된 DLL까지 갱신된 것은 아닙니다.
