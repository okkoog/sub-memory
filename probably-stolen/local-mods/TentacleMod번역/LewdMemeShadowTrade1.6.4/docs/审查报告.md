# 간소화 및 호환성 검토 보고서

2026-11-17 · 암류 거래 1.6.4 · 선행 모드 `lewd_meme` 1.9.2. 이 문서는 현재 결과만 설명합니다. 과거의 긴 보고서와 예전 검증 기록은 별도로 보관했습니다.

## 반영 완료된 변경 사항

| 범위 | 현재 결과 |
| --- | --- |
| 야간 행동 | 자체 무작위 행동 횟수, 취향·피로도 배율, 처녀 상태 상실 회피를 삭제했습니다. 원본 행동을 다시 실행하기 위해 `Train`을 호출하지 않습니다. |

| 피로도 | 본체, 정산을 켠 상자, 알람시계, 작동 중인 함정은 행동 횟수 증가량에 따른 동일 수식을 사용합니다. 다른 위치에서는 매일 25 회복합니다. 장치 안에서 과로한 캐릭터는 5만 회복합니다. 처녀 상태 상실 추가 피로도와 상태 스냅샷은 제거했습니다. |

| 통 보관 | 야간 정산 후 생산 구역 전체를 스캔하며 중첩 아이템도 지원합니다. 원본·확장 신비한 모유를 합산합니다. 모유는 3병, 정액은 8병부터 새 통을 만들 수 있습니다. 네 옵션은 새 통 생성만 제어하며 기존 통 보충은 항상 가능합니다. |

| API 및 상태 | 자체 야간·구역 공개 API, 생산량 스냅샷, 중복된 격자 참조 캐시를 제거했습니다. 게임 저장소에서 해당 구역을 읽는 내부 어댑터는 유지합니다. |

| 치안부 보상 | 이야기 등록 키를 보존하고 완료한 단계에 따라 보상을 복원합니다. 새 아이템의 등급 보완 전에 등록 여부를 확인해 건너뛰던 문제와 구형 저장 데이터의 누락 등록 문제를 수정합니다. 정액 통에도 Ⅱ급 규제를 적용합니다. |
| 수명 주기 | 중복 `PatchAll` 호출은 앞서 제거했습니다. 동적 패치는 owner에 따라 해제하고 전화 연락처 이름 변경은 이 모드 전용 연락처에만 적용합니다. |
| 거래 명부 | 원본 종이책 생성 기능을 재사용합니다. 닫힌 동안에는 거래 내용만 기록하고 데이터가 달라질 때만 페이지를 재구성합니다. 중복 아이템 생성 및 아이콘 대체 처리를 제거했습니다. |
| 사용 횟수·문서 | 통 보관에는 `UseCountHelper`를 재사용합니다. 설명서는 `docs`에 모으고 루트에는 README만 남기며, 구형 보고서와 중복 테스트 안내를 정리했습니다. |

야간 보고는 '오늘 밤 추가된 모유'와 '기존 재고의 통 보관'을 따로 집계합니다. 통 보관을 했다고 그날 밤 생산량을 차감하지 않습니다. 새 통 생성 기준에 미달하거나 생성 옵션을 껐으면 병을 유지하며 이를 생성 실패로 기록하지 않습니다.

원본 모유가 통에 담기지 않는다는 제보에서는, 기존 자동 스캔이 `milk_wondrous`만 인식하고 `wondrous_milk`는 놓친 사실을 확인했습니다. 이제 수동 보충 기능의 아이템 출처 판정을 재사용해 두 종류를 합산하고 같은 신비한 모유 통에 넣습니다. 구형 기능은 원본 모유 3병으로 통을 새로 만드는 회귀 검사에서 실패했습니다. 추가 모유 생산이 없을 때도 원본 생산 구역을 정리합니다. 원본 야간 보고의 생산량과 이 모드의 생산량은 별도로 집계합니다. 제보자의 실제 저장 파일을 읽거나 스크린샷 상황을 검증한 것은 아닙니다.

상자 속 묘상이 정산되지 않는다는 제보는 상자의 실제 배치 위치가 확인되지 않아 플레이어가 겪은 문제의 원인을 단정할 수 없습니다. 코드 검사에서는 이전 구현이 단일 페이지 Tick postfix에 의존하고 상자 내부 첫 번째 저장 페이지만 읽는다는 점을 확인했습니다. 이번에는 콜백 의존성을 제거하고 전체 페이지를 읽도록 변경했으며 전체 `SettleAll` 검사도 추가했습니다. 원본 야간 보고에는 기존 생산량을 그대로 기록하고, 대체 생산으로 차감한 최종 재고 숫자로 덮어쓰지 않습니다. 한 신비한 모유 통에서 먼저 차감했다가 다시 보충하면 사용 횟수의 순변화는 0입니다.

치안부 등록 보상은 간소화 과정에서 삭제하지 않았습니다. 1.5.29 백업과 비교해, 아이템에 기존 불법 태그가 있을 때만 빠져나오는 조건이 이전부터 존재했음을 확인했습니다. 원본 팩토리가 태그를 붙이지 않았거나 구형 아이템에 해금 상태만 있으면 규제 속성이 누락될 수 있었습니다. 이제 먼저 등급을 보완하고 원본 규제품 전환을 호출하며, 구형 저장 파일에서는 처음 문을 열 때 보상을 재적용합니다. 단계 3/4/5는 각각 배란 유도제·정액·묘상 보상을 복원하는 보조 조건으로 사용합니다. 기존 독립 등록 키는 유지하며 이야기 보상을 다시 지급하거나 임무 조건을 바꾸지 않습니다. 게임의 일반 거래는 기본 규제품 추가 가격을 사용하고, 이 모드의 매입상은 독립 가치 계산식을 그대로 적용합니다.

## 유지한 패치와 선택한 절충

현재 정적 목록에는 서로 다른 **Hook 대상 26개(게임 15개, 선행 모드 11개)**와 **transpiler 7개**가 있습니다. 1.5.29에 비해 Hook 대상 2개와 transpiler 1개가 줄었습니다. 전체 행동·생산 교체를 제거한 것이 주된 개선점이지만, 기존 거래와 장치 차단 기능 때문에 패치가 여전히 필요합니다.

| 범위 | 유지하는 이유 |
| --- | --- |
| 원본 `NightlyTick` / `SettleAll` | 행동 전에 과로를 차단하고 뒤에 추가 정산을 실행하기 위해서입니다. 상자 속 캐릭터, 실제 경험치에 반영되는 인원수도 처리합니다. 원본에는 같은 역할의 취소·완료 이벤트가 없습니다. |
| 장치 진입점 4개 | 과로 시 캐릭터 행동·생산을 차단하고 알람시계 기능과 보고서에 같은 자격 조건을 적용합니다. 일반 행동 횟수와 확률은 바꾸지 않습니다. |
| 본체 `BuildWindow` / `EnsureLayout` | 기존 영역과 아이템을 유지하면서 메모 영역을 확장하고 설명서 두 개를 배치합니다. |
| 원본 캐릭터 생성기와 게임 아이템 목록 | 확장 취향, 가치 평가, 액체 콜백 및 이야기 규제 속성을 보완합니다. |
| 원본 폐품 수집 | 원래 있던 0.5초 포획 빈도 제한만 제거하며 다른 포획 조건과 확률은 유지합니다. |
| 매입상·거래 | 게임의 거래 진입점 7개 및 선행 모드 `GuestBox` 필터링을 이용해 단일 아이템 검사, 지급 금액 차이, 추가 매입, 대화 종료 후 정리를 처리합니다. |
| 게임의 기타 진입점 | 범죄·규제, 작은 아이템 클릭 영역, 전화, 저장 전 피로도, 다음 날 전화 동기화를 처리합니다. |

야간 패치는 캐릭터 차단 조건과 설명 갱신 등 기준 명령을 확인한 뒤 호출을 삽입합니다. 전체 IL 지문이 완전히 같을 것을 요구하지 않으므로 다른 모드가 중간에 끼워 넣은 명령을 유지할 수 있습니다. 기준 명령이 맞지 않으면 본체 야간 패치 묶음을 전부 철회하고 원본 정산으로 돌아가며 경고를 남깁니다. 장치 패치는 별도로 설치되고 로그에서도 상태를 따로 표시합니다. 여러 실제 모드를 함께 사용할 때의 실행 순서·동작은 별도로 확인해야 하며 정적 검사가 모든 호환성을 증명하지는 않습니다.

받아들인 동작 변경: 정상 야간 정산은 원본의 행동 강도와 정액 생산율로 돌아갑니다. 추가 모유는 원본 모유를 먼저 차감하고 가능한 한 기존 통에 바로 넣습니다. 과로하면 임신 진행도 멈춥니다. 취향은 텍스트로만 남으며 장치도 이전의 자체 행동 규칙을 사용하지 않습니다. 이전 이야기·거래·식별자·아이템 데이터는 유지됩니다.

## 추가 간소화가 가능한 부분

- **이미지 리소스 수명 주기:** 거래 명부·영수증에 사용되는 `SpriteInjector` 캐시, 잘라낸 이미지와 `PaperChromeIcons`의 아이콘 생성은 아직 쓰고 있습니다. 자체 생성한 `Texture2D`/`Sprite`의 해제 및 캐시 무효화는 완전히 정리하지 못했습니다. 공유 리소스를 삭제하거나 이 문제가 해결됐다고 주장하지 않습니다.
- **종이책 버튼과 노드:** 게임 기본 컨트롤이 대부분의 수명 주기를 담당하지만, 창을 반복해서 열고 닫거나 페이지를 넘길 때 노드를 제대로 해제하는지는 실제 환경에서 확인하지 못했습니다. 현재 버튼 리소스 누수가 발생한다는 증거는 없으므로 개선 가능성을 확정된 오류로 적어서는 안 됩니다.
- **거래 패치:** 모든 거래를 대화를 통한 인도로 바꾸는 설계를 받아들인다면 거래 UI Hook 여러 개를 더 없앨 수 있습니다. 이번 변경에서는 거래 설계를 유지했습니다.
- **메모 영역과 폐품 수집:** 설명서를 수동으로만 지급하고 원본 포획 빈도 제한을 복원한다면 관련 선행 모드 Hook도 제거할 수 있습니다. 하지만 이번에는 현재 동작을 유지했습니다.
- **내부 상태:** 본체 열거, 구역 읽기, 추가 보고 상태는 일부 필요합니다. 공개 구역 API를 삭제했다고 내부에서도 구역 데이터를 읽지 않는 것은 아닙니다.

원본에서 출산 실패 후 대기 중인 출산을 처리하는 방식, 딸의 초상화 승계, 저장 복구는 기존 원본 동작을 따릅니다. 이 모드는 독립적인 수정 기능을 더 이상 추가하지 않습니다. 선행 모드의 안내 문서에는 출산 후 처리, 창 확장, 특수 고객 필터링을 완전히 대신할 수 있는 인터페이스가 제공되지 않습니다.

## 검증 기록과 범위

이 검사는 통제된 엔진 경계에서 실제 후보 어셈블리와 변환된 원본 캐릭터·전체 정산 IL을 실행합니다. 통합 진입점은 실제 prefix/postfix/finalizer를 호출하지만, PowerShell 안에 런타임 detour를 설치하거나 Unity 장면 및 사용자 저장 파일을 불러오지는 않습니다. 공식 패키지는 제작자 환경의 `ModScanner`를 통과했고 `ShadowTrade.dll` 1.6.4로 배포됐으며 후보와 같은 해시입니다. 업데이트 후에는 게임을 다시 시작해야 합니다.
