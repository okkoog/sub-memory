# 개발 안내

적용 대상: 암류 거래 1.6.4. 확인한 선행 모드 버전: `lewd_meme` 1.9.2.

## 빌드와 배포

`Mods` 디렉터리에서 다음 명령을 실행합니다.

```powershell
dotnet build './LewdMemeShadowTrade/Source/MidnightPawn.csproj' -c Release
```

프로젝트는 게임의 `Probably Stolen_Data/Managed`와 `Mods/lewd_meme1.9.2/MidnightPawn.dll`을 참조합니다. 경로가 다르면 MSBuild 속성 `GameManaged`, `OriginalModAssembly`로 바꿀 수 있습니다. 선행 모드 참조에는 `OriginalMod` 별칭을 사용하며, 배포 패키지에 해당 DLL을 복사하지 않습니다.

`Directory.Build.props`는 `bin/obj` 출력물을 시스템 임시 폴더의 `lewd_meme_remake-build` 아래에 저장합니다. 실제 산출물 경로는 빌드 출력에서 확인합니다. 배포 시 manifest 버전과 AssemblyInfo를 함께 갱신하고 후보 `ShadowTrade.dll`을 모드 루트로 복사하세요. 테스트용 DLL, 선행 모드 DLL 또는 컴파일 중간 파일은 패키지에 포함하지 않습니다.

선언형 Harmony 패치는 모드 로더가 설치하도록 맡깁니다. 동적 호환 패치는 아이템 목록이 초기화되고 로더가 이 모드를 등록한 뒤 설치합니다. 다른 모드에 대한 리플렉션은 선언된 선행 모드와 `ModReflect`의 허용 범위로 제한하고, 비활성화할 때는 해당 owner를 기준으로 패치를 해제합니다.

## 데이터와 기존 저장 파일

| 구분 | 유지되는 값 |
| --- | --- |
| 모드 ID와 대부분의 전용 데이터 네임스페이스 | `lewd_meme_remake` |
| DLL 파일명과 AssemblyName | `ShadowTrade` |
| C# 네임스페이스 | `MidnightPawn`, `MidnightPawn.Game`, `MidnightPawn.Api` |
| 이 모드의 모유 | `milk_wondrous`, `milk_rich`, `milk_diluted` |
| 통 | `barrel_semen`, 세 종류의 `barrel_milk_*` |
| 기존 설명 아이템 및 이미지 태그 | `tentacle_manual_remake`, `MILK_REMAKE_OWN_SPRITE` |
| 원본 촉수 본체 레벨, 경험치 및 딸 식별자 | 원본에서 읽습니다. 이전 전용 값은 필요할 때 이전하고, 딸 태그에는 `MAIDEN_DAUGHTER`를 보완합니다. |

`remake` 문자열은 기존 식별자, 리소스 태그, 빌드용 임시 디렉터리에 계속 사용됩니다. 이를 보존하면 이전 저장 데이터를 알아보는 데 도움이 됩니다. 현재는 네 개의 `auto_barrel_*` 설정 키와 캐릭터 태그 `SHADOWTRADE_EXHAUSTED_REST_DAY`를 사용해 같은 밤에 과로 회복이 중복되지 않도록 합니다. 기존 생산량 배율 및 처녀 상태 회피 설정은 더 이상 읽지 않지만 플레이어의 설정 파일을 삭제할 필요는 없습니다.

현재 저장 방식에는 이전 어셈블리 이름을 지정해 이 모드의 캐릭터 객체를 역직렬화해야 하는 경로가 없습니다. 파일명과 AssemblyName을 함께 바꾼 뒤에도 기존 아이템과 데이터는 ID 및 키로 읽습니다. 다만 외부 확장이 `MidnightPawnRemake`를 정적으로 참조한다면 새 DLL을 참조하도록 변경하고 다시 컴파일해야 합니다. 이 판단은 코드와 통제된 검사 결과에 근거하며, 실제 예전 저장 파일을 다시 읽는 시험까지 포함하지 않습니다.

치안부 보상에는 `liaison_reg_ovulation`, `liaison_reg_semen`, `liaison_reg_maiden` 등록 키 세 개를 유지합니다. 각각 `liaison_stage >= 3`, `>= 4`, `>= 5`도 유효한 조건으로 인정하며, 이는 **다음 이야기 단계**의 값입니다. 등록할 때 먼저 게임 기본 불법 물품 등급을 보완하고, 그다음 `PermitHelper.SetRestrictedClass`와 `ContrabandHelper.RemoveContrabandStatus`로 규제품으로 전환합니다. 추가 가격은 게임이 처리합니다. 예전 저장 파일을 불러오면 기존 '처음 문 열기' 복구 단계에서 보상을 다시 적용합니다. 새 아이템, 원본 세력 팩토리 및 직접 생성한 정액 통도 처리하며 새로운 Hook을 추가하지 않습니다. 이야기 진행에 제출하는 정액은 여전히 병 제품만 인정합니다.

## 확장 인터페이스

다음 인터페이스는 **삭제**됐습니다: `NightlySettlementApi`, `NightlySettlementContext`, `BodyZoneInfo`, `TentacleBody.GetZoneInfo`. 자체 행동 배율, 임신 배율, 생산 배율, 처녀 상태 회피, 무효화된 예전 설정의 보조 진입점도 삭제했습니다. 호환용 빈 구현체는 제공하지 않으므로 해당 인터페이스에 의존하던 외부 확장은 새 방식으로 이전해야 합니다.

훈련, 통계, 딸 판정, 촉수 본체 레벨·경험치, 일반적인 안전한 아이템 배치는 선행 모드의 `MidnightPawn.Api.TentacleApi`를 사용합니다. 정확한 사용법은 실제 DLL과 선행 모드 폴더의 《子模组接入指南.md》를 기준으로 해야 합니다. 제작자가 확인한 1.9.2 DLL의 공개 레벨 인터페이스는 여전히 5로 제한돼 있습니다. 따라서 이 확장은 공개 인터페이스 값과 원본의 `body_lv` 저장값 중 **큰 값**을 사용하며, 확장 자체에서 레벨 상한을 두지 않습니다. 원본 모드 파일은 변경하지 않습니다. 차기 공개 인터페이스가 더 높은 레벨을 반환하면 그대로 지원합니다.

피로도 상태는 원본의 행동 횟수와 밤 시작 시 임신 상태만 읽습니다. 처녀 상실 이벤트를 구독하거나 처녀 상태를 저장하지 않고 고정 사건 피로도를 추가하지도 않습니다. 모든 장치가 같은 레벨 계수 표를 사용하며, 계수가 0일 때는 최소 +1 보정 없이 바로 0을 반환합니다. 장치 밖 회복에서는 본체, 정산을 켠 침식 구역의 직접 묘상 상자, 알람시계, 작동 중인 함정을 제외하고 날짜별로 중복을 방지합니다.

`OnMaidenTrained`는 원본 행동 이후, 임신 진행과 생산 이전에 호출되므로 행동 **전** 과로 차단이나 행동 **후** 통 보관 처리에 사용할 수 없습니다. 이런 이유로 이 모드에는 소수의 삽입형 Harmony 패치가 남아 있습니다. 일반 행동과 임신 관련 원본 명령은 하나씩 그대로 유지합니다.

촉수 본체의 `SettleAll` 주 루프가 끝난 뒤 경험치 및 원본 야간 보고가 생성되기 전에 추가 대상의 원본 `NightlyTick`을 일괄 호출합니다. 한 보관 페이지의 Tick postfix에 의존하지 않습니다. 캐릭터는 정산 차례별로 중복 제거하며, 침식 구역의 직접 묘상 상자는 게임의 `GetBodyStorage`를 사용해 모든 보관 페이지를 읽습니다. 피로도 계산용 구역 확인도 같은 수집 방법을 사용합니다. 상자 안에서 한 단계까지만 처리하며 다른 컨테이너로 재귀 진입하지 않습니다.

이 모드의 모유는 1개씩 생성할 때 원본 병 제품을 먼저 차감하고, 없으면 신비한 모유 통에서 사용 횟수를 차감합니다. 같은 종류의 통에 곧바로 보충하는 방식을 우선합니다. 사용 횟수 처리는 `UseCountHelper`를 재사용합니다. 마지막 병이거나 다른 종류 때문에 비어 버리는 원본 통은 게임 기본 `Expel`로 잠시 꺼낸 뒤 성공하면 삭제하고, 실패하면 `UncheckedAccept`로 같은 객체를 원래 칸에 돌려놓습니다. 중첩 개수와 통 사용 횟수도 원상복구하며 대체 원본 아이템을 새로 생성하지 않습니다. 한 통이 차감 대상이면서 동시에 보충 대상인 경우에는 먼저 차감한 다음 보충해 마지막 횟수에 도달했을 때 통이 조기에 파괴되지 않도록 합니다.

야간 말미의 통 보관과 수동 보충은 `ItemFactory.IsBarrelSourceItem` 판정을 함께 사용합니다. 이 모드의 `milk_wondrous`와 원본의 `wondrous_milk`를 합산하며 **3개 이상**일 때만 신비한 모유 통을 새로 만듭니다. 다른 종류는 각각 별도로 판정합니다. 원본 생산은 그대로 유지하고 추가 모유 생산을 위해 차감되지 않은 병도 통 보관에 참여합니다. 기존 통에 보충하는 동작은 새 통 생성 옵션이나 임계값의 영향을 받지 않습니다.

독립적인 **TooltipApi**는 계속 제공됩니다. `ShadowTrade.dll`을 참조한 다음 다음 이벤트를 구독하세요.

```csharp
MidnightPawn.Api.TooltipApi.BuildTooltip += context =>
{
    // context.Item, context.Builder, context.Section
};
```

이벤트는 툴팁의 각 구간에 대해 실행되며 구독자별 예외를 개별적으로 처리합니다. 사용 가능한 구간은 `Body`, `CorruptTentacle`, `TentacleBox`, `Barrel`, `Maiden`, `Other`입니다. 직접 구독한 확장은 언로드 시 반드시 구독을 해제해야 합니다.

## 검증 진입점

현재 유지보수 중인 검사는 `Mods/.compat-audit/shadowtrade/`에 모여 있으며, 모드 실행에는 포함되지 않습니다. 빌드한 후보 DLL의 경로로 다음 명령을 실행합니다.

```powershell
pwsh -NoProfile -File './.compat-audit/shadowtrade/test-nightly.ps1' -Candidate '<후보 DLL의 절대 경로>'
pwsh -NoProfile -File './.compat-audit/shadowtrade/test-ledger-barrel.ps1' -Candidate '<후보 DLL의 절대 경로>'
pwsh -NoProfile -File './.compat-audit/shadowtrade/test-contracts.ps1' -Candidate '<후보 DLL의 절대 경로>'
pwsh -NoProfile -File './.compat-audit/shadowtrade/scan-package.ps1' -Package '<모드 폴더의 절대 경로>' -DllName 'ShadowTrade.dll'
```

검사는 후보 어셈블리, 원본 캐릭터 정산 루프 및 완전한 `SettleAll`에 삽입된 IL과 기본 게임 사용 횟수 처리 메서드를 직접 실행합니다. 장면, 리소스, 난수, 경험치 반영 및 아이템 배치 경계는 통제된 조건으로 교체합니다. 통합 검사는 실제 prefix/postfix/finalizer 메서드를 호출하지만, PowerShell 환경에서 원본 Harmony 런타임 detour를 설치하지는 않습니다. 이 검사는 플레이어 저장 파일을 쓰지 않습니다. 통제된 실행은 Unity의 실제 게임 실행과 같지 않습니다. 현재 결과와 파일 해시는 해당 검사 폴더에 있습니다. 게임에서 추가 확인할 사항은 검토 보고서를 참고하세요.
