# 自学习强化机：兼容性说明

适用版本：`Pen_mod_selflearning` 当前工程版本。  
本文说明其他 mod 可以通过哪些 tag / 数据影响自学习机的：

- 自学习进度（模组属性成长）；
- 自学习上限（每个模组的封顶值）；
- 哪些原版修改**不会**被本 mod 识别。

## 1. 本 mod 如何识别“可成长模组”

一个模组会被 `AdvanceAll` / `AdvanceOne` 处理，需要满足：

1. 位于自学习机的模组仓；
2. `MODULE_TAG`；
3. 至少满足以下之一：
   - `MODULE_EFFECT1_TAG == "MODULE_EFFECT_LEARNING_ALGORITHM"`；
   - `MODULE_EFFECT2_TAG == "MODULE_EFFECT_LEARNING_ALGORITHM"`；
   - 任意一个 `LEARNING_ALGO_MAX_*_INT` 存在。

只有 `BONUS_PERCENTAGE_*` 而没有学习词条 / max tag 的模组，不会被当作自学习模组。

## 2. 可识别的自学习进度修改

### 2.1 三条属性

本 mod 读取并写入：

```text
BONUS_PERCENTAGE_PERFORMANCE_INT
BONUS_PERCENTAGE_EFFICIENCY_INT
BONUS_PERCENTAGE_QUALITY_INT
```

每次夜间推进时：

```text
当前值 cur 读取 BONUS_PERCENTAGE_<ATTR>_INT
下一次值 = min(cur + 本次推进次数, 上限)
```

因此外部 mod 直接修改这些 tag：

- 改大 → 下一次推进从新值继续；
- 改小 → 下一次推进从新值继续；
- 改成负数 → 负属性仍向 0 成长（前提是没有正 max 或 max 按规则处理）。

### 2.2 每晚推进次数

当前公式：

```text
基础 = 每模组成长值 + mod 设置「额外推进次数」
额外 = floor(机器 TEMP 质量% / 质量转化比例)
每晚 = 基础 + 额外
```

每模组成长值：

```text
优先读取机器 tag SELF_LEARNING_GAIN_PER_USE_INT
没有该 tag 时使用原版语义 1
```

对应原版 `LEARNING_ALGO_GAIN_PER_USE` 的语义。

外部 mod 如果只修改原版 `OnUsedLearningAlgo` 或私有常量，**不会**改变本机的每晚次数；本机不走原版 `OnUsedLearningAlgo`。

### 2.3 质量会影响额外次数

`PlannedAdvances` 读取：

```text
每模组 TEMP_PERCENTAGE_QUALITY_INT
缺失时回退 BONUS_PERCENTAGE_QUALITY_INT
```

再对模组求和，得到机器 TEMP 质量。

因此：

- 修改模组质量 BONUS/TEMP；
- 修改节点/相邻加成导致 TEMP 质量变化；

都会影响“质量额外推进次数”。

注意：

- 本机不使用机器上的单个 `TOTAL_PERCENTAGE_QUALITY_INT` 作为唯一来源；
- 它按模组仓逐项读取 `TEMP` / `BONUS` 后求和。

### 2.4 外部调整成长值：SELF_LEARNING_GAIN_PER_USE_INT

外部 mod 直接写机器 tag：

```csharp
machine.ModifyTag("SELF_LEARNING_GAIN_PER_USE_INT", ts =>
{
    ts.Enable();
    ts.SetInt(9);
}, true);
```

此时：

```text
基础 = tag 9 + 设置 1 = 10
```

规则：

- 优先读取机器上的 `SELF_LEARNING_GAIN_PER_USE_INT`；
- 没有 tag 时按原版语义 `1`；
- 负数按 0 处理；
- 设置项 `base_advances` 仍然作为“额外推进次数”叠加：
  ```text
  总基础 = 成长 tag（无则 1） + base_advances
  ```

配置项本身也可以通过官方 `ModConfig` API 查询，但测试补丁使用 tag 作为成长值入口，设置只用于验证 `tag + setting` 的组合。

`base_advances` 设置范围：`0–9`，默认 `1`；总基础 = 成长值 + 此设置。

## 3. 可识别的自学习上限修改

本 mod 每个属性实时读取：

```text
LEARNING_ALGO_MAX_PERFORMANCE_INT
LEARNING_ALGO_MAX_EFFICIENCY_INT
LEARNING_ALGO_MAX_QUALITY_INT
```

`AdvanceOne` 的规则：

```text
如果存在 max tag：
    使用该值
否则如果属性当前值是负数：
    max = 0（负属性向 0 成长）
否则：
    不推进该属性
```

然后：

```text
next = min(cur + times, max)
```

### 3.1 外部修改上限的效果

| 外部操作 | 本机行为 |
|---|---|
| 把 max 改大 | 下一夜按新上限继续成长 |
| 把 max 改小 | 下一夜按新上限封顶 |
| max 小于当前值 | 跳过，不把值往回改 |
| 删除正属性的 max | 该属性不再成长 |
| 删除负属性的 max | 按 0 处理，继续向 0 成长 |
| 同时修改 BONUS 和 max | 下一夜按两者当前值计算 |

上限没有缓存，每次推进都重新读取。

### 3.2 授予时的上限

本 mod 授予「自学习算法」时调用原版：

```csharp
ModuleEffectHelper.InitLearningAlgo(mod)
```

因此：

- 如果其他 mod 补丁了 `InitLearningAlgo` 的 max 倍率，授予时会影响；
- 授予后其他 mod 再改 `LEARNING_ALGO_MAX_*`，本机下一次推进会读取新值；
- 但**修改基础 BONUS 后不会自动重算 max**，需要外部 mod 自己同步 max tag。

## 4. 不会被本 mod 识别的修改

以下修改不会影响自学习机：

1. 只修改 `LEARNING_ALGO_GAIN_PER_USE` 常量；
   - 原版当前实现其实没有读取该常量，`OnUsedLearningAlgo` 内部写死 `+1`；
   - 本机也不读取它；外部 mod 应改 `SELF_LEARNING_GAIN_PER_USE_INT` tag。
2. 只补丁 `OnUsedLearningAlgo` 的每次 `+N`；
   - 本机不调用该方法。
3. 只修改原版机器的 `onCycleEndSlotItemFunc` / 基础 cycle；
   - 本机使用自己的 `onCycleEndSlotItemFunc`。
4. 只修改机器上的某个总加成 tag，而没有更新模组仓的 `TEMP` / `BONUS`。
5. 授予后修改模块基础 BONUS，但不更新 `LEARNING_ALGO_MAX_*`；
   - 上限仍是授予时写入的旧值。

## 5. 推荐的外部 mod 接入方式

### 5.1 修改进度

```csharp
mod.ModifyTag("BONUS_PERCENTAGE_PERFORMANCE_INT", ts =>
{
    ts.Enable();
    ts.SetInt(newValue);
}, true);
```

三条属性同理：

```text
BONUS_PERCENTAGE_PERFORMANCE_INT
BONUS_PERCENTAGE_EFFICIENCY_INT
BONUS_PERCENTAGE_QUALITY_INT
```

### 5.2 修改上限

```csharp
mod.ModifyTag("LEARNING_ALGO_MAX_PERFORMANCE_INT", ts =>
{
    ts.Enable();
    ts.SetInt(newMax);
}, true);
```

建议始终保证：

```text
BONUS <= LEARNING_ALGO_MAX
```

负属性可以不写 max，本机会按 0 处理；如果要显式封顶，也可以写入 0 或对应值。

### 5.3 修改后刷新

本机每次夜间推进前会重新计算模组 TEMP，但外部 mod 修改 tag 后，UI 可能仍显示旧值。

推荐外部 mod 在修改后调用原版：

```csharp
ModuleEffectHelper.ComputeAllModuleTempStat(modules);
ModuleHelper.ComputeModuleEffect(moduleGrid, null, machine);
ModuleHelper.ApplyBasicModuleEffect(moduleGrid, null, machine);
```

或等待本机下一次 tooltip / 夜间刷新。

### 5.4 新增自定义自学习模组

建议：

1. 使用原版 `MODULE_EFFECT_LEARNING_ALGORITHM`；
2. 调用 `ModuleEffectHelper.InitLearningAlgo` 初始化 max；
3. 如需自定义上限，再写 `LEARNING_ALGO_MAX_*`；
4. 保持 `BONUS` 在 max 范围内；
5. 不要只写自定义 tag 而绕过上述官方 tag。

## 6. 兼容性对照表

| 修改内容 | 是否识别 | 说明 |
|---|---|---|
| `BONUS_PERCENTAGE_*` | 是 | 每次推进实时读取 |
| `LEARNING_ALGO_MAX_*` | 是 | 每次推进实时读取 |
| `SELF_LEARNING_GAIN_PER_USE_INT` | 是 | 覆盖每次成长值，优先于原版 1 |
| `TEMP_PERCENTAGE_QUALITY` | 是 | 影响质量额外次数 |
| 节点/相邻质量加成 | 是 | 通过 TEMP 质量间接影响 |
| `InitLearningAlgo` 的 max 规则 | 是 | 授予时调用原版 |
| `OnUsedLearningAlgo` 的 +N | 否 | 本机不调用 |
| `LEARNING_ALGO_GAIN_PER_USE` | 否 | 原版未实际使用，本机固定 1 |
| 原版机器基础 cycle | 否 | 本机有独立 cycle |
| 只改总加成 tag 不改模组 tag | 否 | 本机按模组仓读取 |
| 只改基础 BONUS 不改 max | 部分 | 进度变，但上限仍是旧 max |

## 7. 一句话总结

外部 mod 想影响自学习机，最可靠的方式是：

```text
改 BONUS_PERCENTAGE_*
改 LEARNING_ALGO_MAX_*
改 SELF_LEARNING_GAIN_PER_USE_INT
改模组 TEMP 质量
```

不要依赖修改 `OnUsedLearningAlgo` 或原版 `LEARNING_ALGO_GAIN_PER_USE` 常量；这些不会改变本机的推进逻辑。
