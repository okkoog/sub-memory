# 集成芯片：兼容性说明

本说明只覆盖四类接入：

1. 密码解序器芯片的接入写法；
2. 3D 打印机芯片的接入写法；
3. 双向拖拽与吸收规则；
4. 不会被本 mod 识别的情况。

> **兼容无需反射，也无需声明或申请任何额外权限。**
> 不需要 `reflection-external`、`files`、`native` 等能力，不需要引用本 mod 程序集。
> 本 mod 只在原版解码芯片自带的「芯片交换」钩子会误拦截反向拖拽时，用一个窄 Harmony 前缀接管 `GameItem.MayTarget / CanTarget / Target`；它不影响第三方芯片的写法，也不会改动你的物品。

集成芯片在玩家拖拽的瞬间**直接读取物品自身的 tag**，不维护任何芯片白名单，所以第三方 mod 新增的芯片（先装后装、加载顺序不同）都能直接整合，不需要适配代码。

## 1. 密码解序器芯片的接入写法

### 必需

| tag | 类型 | 说明 |
|---|---|---|
| `DESEQUENCER_TARGET_ID_TAG` | string | 解序目标物品 id。必须是**已注册**、类型为 `ACCESS_CARD`、且不是 `blank_keycard` 的物品（原版解序器输出槽只收钥匙卡）。 |

### 可选

| tag | 类型 | 缺省行为 |
|---|---|---|
| `PROGRESS_ITEM_TAG` + `PROGRESS_ITEM_TARGET_TAG` | tag / int | 原版工作量。缺失时按 0 处理（对应机器上会立刻完成）。 |

推荐直接使用原版 API 写入：

```csharp
item.ModifyTag("DESEQUENCER_TARGET_ID_TAG", s => s.Enable().SetString("my_keycard"));

// 工作量 + PROGRESS_ITEM_TAG（第二参数为工作量）
MachineProgressHelper.InitProgressSourceItem(item, 100);

// 与原版芯片一致的拖拽音
AudioHelper.InitSmallModule(item);
```

说明：

- 不需要把物品声明成 `MODULE` 类型，也不需要加任何「集成芯片」专用 tag；
- 集成芯片会自己写入派生的 `DESEQUENCER_TARGET_ID_TAG` / `PROGRESS_ITEM_*`，不要在你的芯片里预先写这些目标值到集成芯片上。

## 2. 3D 打印机芯片的接入写法

### 必需

| tag | 类型 | 说明 |
|---|---|---|
| `PRINTER_CHIP_TAG` | tag | 原版打印机芯片槽的准入标签。 |
| `PROGRESS_ITEM_TAG` | tag | 任务标记。 |
| `PROGRESS_ITEM_TARGET_ITEM_ID_TAG` | string | 输出物品 id，必须**已注册**。 |

### 会被快照保存并还原的 tag

集成芯片会保存来源芯片上所有以 `PRINTER_` / `PROGRESS_` / `REQUIRED_` 开头、且已启用的 tag（跳过 `PROGRESS_ITEM_SHOW_DEFAULT_TOOLTIP`），切换任务时整体还原。常见的有：

```text
PRINTER_CHIP_TAG
PRINTER_MELEE_CHIP_TAG / PRINTER_FRAME_CHIP_TAG / PRINTER_GUN_PART_CHIP_TAG
PROGRESS_ITEM_TAG
PROGRESS_ITEM_TARGET_TAG                    // 工作量
PROGRESS_ITEM_TARGET_ITEM_ID_TAG            // 输出物品 id
PROGRESS_ITEM_TARGET_ITEM_COUNT_TAG         // 输出数量
PROGRESS_ITEM_USE_ADDITIONAL_ITEMS           // 需要材料
REQUIRED_ITEM_TYPE_COUNT_TAG
REQUIRED_ITEM_ID_<i> / REQUIRED_ITEM_COUNT_<i>
PROGRESS_ITEM_REQUIRED_MACHINE_TAG           // 需要的机器模块，如 "CNC Module"
PROGRESS_ITEM_REQUIRED_MACHINE_TAG_COUNT
PROGRESS_ITEM_REQUIRED_MACHINE_TAG_<i>
```

推荐使用原版 API 写入（等价于原版打印机芯片）：

```csharp
item.EnableTag("PRINTER_CHIP_TAG");

// 输出物品 + 工作量 + 输出数量（最后一个参数是数量）
MachineProgressHelper.InitProgressSourceItem(item, 24, "my_printed_item", true, 2);

// 需要材料（单一 / 两种）
MachineProgressHelper.SetSingleAdditionalRequiredItem(item, "printer_plastic", 2);
MachineProgressHelper.SetDualAdditionalRequiredItem(
    item,
    (itemID: "scrap_metal", count: 3),
    (itemID: "common_electronic", count: 1));

// 需要机器模块（例如 CNC）
MachineProgressHelper.AddRequiredMachineTag(item, "CNC Module");

AudioHelper.InitSmallModule(item);
```

说明：

- 特殊类型（近战/枪身/枪件）的批量与质量逻辑由原版 `FinishPrinting` 处理，只要对应 `PRINTER_*_CHIP_TAG` 被快照保留即可；
- 输出数量保存在 `PROGRESS_ITEM_TARGET_ITEM_COUNT_TAG`，切换任务后按该数量打印；
- **快照只覆盖上述三个前缀**。如果你把任务数据写在自己命名的 tag 下（例如 `MYMOD_PRINT_TARGET`），集成芯片不会复制它。

## 3. 双向拖拽与吸收规则

- **两个方向都能吸收**：把芯片拖到集成芯片上，或把集成芯片拖到芯片上都可以；
- 同一背包内也能反向吸收（原版解码芯片自带的 chip-swap 钩子会被本 mod 的窄补丁绕过）；
- **只吸收玩家拥有的芯片**：物品需要带 `IS_OWNED_TAG`，且祖先容器也归玩家所有；柜台/货架上的未拥有芯片会被拒绝；
- 同一目标（解序器）或同一任务快照（打印机）重复拖入 → 提示「芯片信息已包含」，**不消耗**芯片；
- 两块集成芯片之间不会互相吸收；
- 解序器芯片的目标必须是已注册的 `ACCESS_CARD`；打印机芯片的输出物品必须已注册；
- 来源 mod 被卸载后，对应条目会在**下一次载入存档时被清除**（连同已不存在的目标物品/材料），避免存档里留下悬空 id；全部不可用时芯片会惰性化，不会向机器提供无效任务。

## 4. 不会被本 mod 识别的情况

以下写法不会被识别或会被拒绝：

1. 只用自己的 tag 描述目标，没有 `DESEQUENCER_TARGET_ID_TAG`（解序器）或 `PRINTER_CHIP_TAG` + `PROGRESS_ITEM_TARGET_ITEM_ID_TAG`（打印机）；
2. 解序器目标不是 `ACCESS_CARD`、是 `blank_keycard`、或目标物品未注册；
3. 打印机芯片缺少输出物品 id，或输出物品未注册；
4. 打印机任务数据写在 `PRINTER_` / `PROGRESS_` / `REQUIRED_` 之外的自定义 tag 下（不会被快照）；
5. 物品是 `MACHINE` 类型、带 `CONTAINER_TAG`、或带 `DESEQUENCER_STATE_TAG`（跑过一夜的解序器自身也会带目标 tag）；
6. 芯片不归玩家所有（柜台/货架/未拥有容器内）；
7. 物品本身带 `PEN_IC_COUNT` 或 `PEN_PC_COUNT`（即另一块集成芯片，含本 mod 物品的副本）；
8. 期望通过反射、Hook 私有方法或申请额外权限来「强制兼容」——本 mod 不读取这类接口。

本 mod 的兼容接口就是：

```text
DESEQUENCER_TARGET_ID_TAG
PRINTER_CHIP_TAG
PROGRESS_* / REQUIRED_* / PRINTER_* 原版协议族
原版 MachineProgressHelper API
```

这些都不需要反射或额外权限。
