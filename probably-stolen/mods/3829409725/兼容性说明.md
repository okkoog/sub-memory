# 移液枪模组兼容性说明

## 1. 概要

本说明适用于：

| 项目 | 值 |
|---|---|
| 主模组 ID | `Pen_mod_pipette` |
| 游戏版本 | `0.46D` |
| 主模组版本 | `1.1.4` |
| 规则文件 | `Rules/hydra.json` |
| 外部补丁文件 | `PipetteReactions.json` |
| 外部补丁方式 | JSON 数据补丁 |

移液枪模组读取规则后，会：

1. 加载自身 `Rules/hydra.json`；
2. 扫描已启用 Mod 的 `PipetteReactions.json`；
3. 加载其中的 `modes`；
4. 应用其中的 `patches`；
5. 重新编译并校验受影响的反应。

补丁只修改内存中的规则，不写回任何原始 JSON 文件。

### 通用外部规则延迟加载

自动移液枪不内置任何第三方模组的专用兼容 JSON，只识别标准文件：

```text
Mods/<模组目录>/PipetteReactions.json
```

如果第三方液体在自动移液枪初始化之后才注册，液体注册数量变化时会重新扫描所有已启用模组的 `PipetteReactions.json`。该机制不检查模组 ID，也不检查液体 ID，适用于任何按相同格式提供规则的模组。

CorpPresence 等模组的兼容规则应由对应模组或独立补丁模组自行提供；主模组发布包不包含这些专用 JSON。

## 2. 数据补丁模组的要求

### 2.1 必须有载入程序集

游戏官方 `ModLoader` 要求每个 Mod 的 `manifest.xml` 至少声明一个 DLL：

```xml
<Assemblies>
  <Assembly>你的补丁模组.dll</Assembly>
</Assemblies>
```

只有：

```text
manifest.xml
PipetteReactions.json
```

而没有 DLL 的纯数据 Mod，不会被游戏识别，移液枪模组也无法扫描到它。

### 2.2 推荐的最小载体 DLL

补丁模组可以只放一个空实现 DLL：

```csharp
public sealed class PatchCarrier : IMod
{
    public void Init(ModManifest manifest) { }
    public void OnEnable() { }
    public void OnDisable() { }
}
```

要求：

- 不引用 `Pen_mod_pipette.dll`；
- 不使用反射；
- 不修改原版代码；
- 不注册物品；
- 所有实际规则放在 `PipetteReactions.json`。

### 2.3 前置

建议在补丁模组清单中声明：

```xml
<Prerequisites>
  <Mod>Pen_mod_pipette</Mod>
</Prerequisites>
```

---

## 3. 补丁文件位置

```text
Mods/<补丁模组目录>/PipetteReactions.json
```

移液枪模组会在启动时读取所有已启用 Mod 的该文件。

---

## 4. 补丁结构

根节点只使用：

```json
{
  "patches": []
}
```

不再需要 `apiVersion`，该字段已移除。

每条 patch 至少包含：

```text
mode
```

可选字段：

```text
stage
set
remove
replace
addStage
before
after
```

---

## 5. 支持的补丁操作

### 5.1 修改已有字段

```json
{
  "mode": "reducing",
  "stage": "nomore",
  "set": {
    "temperatureMin": 44,
    "temperatureMax": 55
  }
}
```

说明：

- `set` 是递归合并，不是整段替换；
- 适合只改温度、比例、`targets` 的 floor 等字段。

### 5.2 删除字段

```json
{
  "mode": "fanta",
  "stage": "fanta",
  "remove": ["temperatureMin", "temperatureMax"]
}
```

### 5.3 替换整个阶段

```json
{
  "mode": "reducing",
  "stage": "nomore",
  "replace": {
    "id": "nomore",
    "kind": "reaction",
    "substrate": {
      "liquid": "dream_cap_extract",
      "locations": ["target"]
    },
    "reagent": {
      "liquid": "reducing_agent",
      "locations": ["pipette"]
    },
    "temperatureMin": 44,
    "temperatureMax": 55
  }
}
```

注意：

- `replace` 会替换整个 stage；
- 建议显式写 `id`；
- 替换后必须能重新通过公式编译和阶段校验。

### 5.4 新增阶段

```json
{
  "mode": "chlorine",
  "addStage": {
    "id": "heavy_metal",
    "label": "重金属",
    "kind": "reaction",
    "substrate": {
      "liquid": "water",
      "locations": ["target"]
    },
    "reagent": {
      "liquid": "chlorine",
      "locations": ["target", "pipette"]
    },
    "targets": {
      "heavy_metal": {
        "floor": {
          "type": "absolute",
          "value": 0
        }
      }
    },
    "potency": 1
  },
  "before": "decontaminate"
}
```

插入位置：

- `before`：插入到指定 stage 前；
- `after`：插入到指定 stage 后；
- 都不填：追加到末尾。

## 6. 加载顺序与冲突

### 6.1 顺序

```text
移液枪模组自身规则
→ 外部 modes
→ 外部 patches
→ 重新编译/校验
```

### 6.2 冲突

- 多个补丁 Mod 修改同一字段：按 Mod 加载顺序，后加载覆盖前者；
- 目标 `mode` 不存在：记录 Warn，跳过；
- 目标 `stage` 不存在：记录 Warn，跳过；
- `addStage` 的 id 已存在：记录 Warn，跳过；
- 补丁后公式编译或校验失败：拒绝该补丁，保留原规则。

---

## 7. 与旧规则的关系

- 规则文件不再包含 `apiVersion`；
- 不再读取或校验版本字段；
- 旧版本字段不会参与拒绝判断；
- 现有阶段仍按 `kind` 和字段内容编译；
- 第三方补丁不需要引用主模组 DLL。

---

## 8. 日志

补丁成功：

```text
pipette patch applied mode=chlorine stage=heavy_metal from=Pen_mod_pipette_patch_test
```

补丁失败：

```text
pipette patch skipped from=...: unknown mode ...
pipette patch rejected from=...: invalid mode ...
```

排查顺序：

1. 补丁 Mod 是否启用；
2. `manifest.xml` 是否声明了 DLL；
3. `PipetteReactions.json` 是否在 Mod 根目录；
4. 日志是否有 patch applied/skipped/rejected；
5. 修改后是否重启游戏。

---

## 9. 已知限制

- 当前仍按“一阶段一操作”推进，不会在一次加液中连续执行多个阶段；
- 补丁只对当前启动有效，重启后重新加载；
- 禁用或移除补丁 Mod 后，原规则恢复；
- 未知 JSON 字段会被忽略；
- 补丁不提供脚本能力，不能执行任意代码；
- 不支持没有 DLL 的纯数据 Mod；
- 主模组不内置任何第三方模组的专用兼容 JSON；
- 补丁不会修改原始 `hydra.json`。

---

## 10. 测试补丁模组

测试模组：

```text
Pen_mod_pipette_patch_test
```

当前验证内容：

1. 在 `chlorine` 模式中新增 `heavy_metal` 阶段；
2. 重金属按 `1µL 氯 : 1µL 重金属` 消耗；
3. 将 `decontaminate` 的化学污染物 floor 改为 `absolute 0`，完全去污。

该模组仅用于验证 patch 机制，不是正常游玩必需内容，验证完成后可移除。
