# 上层区的富家千金爱上在下层区开当铺的我：埃莉诺剧情扩展

《深空当铺：可能是偷的 / Probably Stolen》Eleanor 个人剧情线重制 MOD。

- 游戏版本：1.0.0.14（public 与 open_beta 当前为同一构建；同时保留 1.0.0.13 / 0.46D 兼容）
- MOD版本：1.03
- 内容尺度：全年龄
- 语言：简体中文 / English（剧情与 UI 均已翻译）

## 1.03：修复第6章求食援助分支

- 第6章（`c05`）埃莉诺求食来访现在与原版 Eleanor4 一样以 0 预算到店；此前固定 40 预算会被店铺吸引力／特性加成抬高（玩家看到约 68），把赠食变成购买，导致小额或免费食物误播“你开的是店，不是救济站”。
- 现在任何被她收下的食物都算真实援助，必定进入道谢与道歉分支；只有什么都没给时才播放拒绝台词。
- 包含 1.02 的后期回应选择与路线修复、1.01 的上层顾客饰品判定修复，以及一轮对白与留白整理；不改路线、奖励或 E1—E14。

## 1.02：后期回应选择化与路线修复

- 后宫线 `dr07`、`dr09`、`dr14` 增加玩家回应选择；莉迪亚的告白后不再只有被动听独白。
- 埃莉诺 `c18` 关系稳定段、侍从线 `m24`、革命军线 `R14` 也加入同类短选择；双恋线选项从 13 个增加到 22 个。
- 后宫线不再触发普通恋爱线的拾荒协助事件；`CompleteCore` 也不再在后宫线弹出该事件解锁提示。
- 包含 1.01 的全部上层顾客饰品判定修复；当前仍为全年龄内容。

## 1.01：后宫线饰品对所有上层顾客生效

- 后宫线三件橱窗饰品此前只识别 `upperLowerVisitor`、`upperLowerVisitorLuxury`、`ulDiscerningShopper` 三个顾客 ID；囤水者（`waterStockpiler`）等其他正规上层顾客没有被计入，导致座饰预算和银饰小费不生效。
- 现在按 `FACTION_UPPER_LEVEL` 判定，覆盖所有上层买家，包括 `SELLNBUY` 的上层顾客；囤水者、私人厨师、医院采购、上层女仆、私人安保等都会获得对应效果。
- 仍然排除：具名剧情客户、原版埃莉诺剧情、其他 MOD 客户以及不做购买的顾客。黑市、下层、拾荒者不生效。
- 三件饰品仍只在真实陈列时生效，每访小费最多 150；只改顾客判定，不改奖励数值、路线或结局。

## v0.6 内容结构

- 从第 23 天起重写 Eleanor 的完整个人线，共 23 章核心剧情 + 路线丙 8 段 + 路线丁 4 段 + 第 60 天后的可选短日常。
- 主要载体是原生柜台访客、买卖、物品检视、举报、拘捕与新闻，不新建后间、通讯中心或案卷 UI。
- 关键行为会改变结果：公平收购、压价、让利、零价食物援助、假叔叔箱子、举报、警告、800 信用点调查款、数据盘保管人、保护渠道与最终公开/归还决定。
- 路线甲“把她接回来”：归还研究换母亲来到下层区，可发展完整恋爱。
- 路线乙“留下种子”：先落实保护，再处理研究；母女在下层区团聚，研究有机会公开。
- 路线丙“种子与代价”：未保护便公开，母亲遇害，Eleanor 加入革命军。
- 路线丁“生意做到这里”：擅自处置数据盘、收私钱、瞒着她公开或正常退出，关系结束。
- 朋友路线：可以救人而不恋爱；不会撤销救援成果。

## 行为与状态

- `RomanceState` 分开记录母亲状态、研究/数据盘去向、恋爱状态、工作去向与行为事实，不再用一个 true_ending 布尔值承担所有含义。
- 交易通过 `onItemBought` / `onItemSold` 读取真实成交价，并按物品基础价值判断公平、让利、抬价或压价。
- 拾荒调查款按实际收购收入累计到 800；若玩家收货不足，她会在第 42 天前用其他售货与短工补齐，不会凭空要求玩家掏整笔钱。
- 假叔叔箱子沿用原生物品与举报/拘捕流程；警告她会解除陷阱。举报和“只是起疑”是两回事。
- 被捕后的保释交回原版埃莉诺调度：两天后警官来访，支付 500 信用点或治安部声望 40 免费担保，次日释放回访后接回重制章节；可先回去筹钱。旧 MOD 被捕存档使用原版迁移规则补齐日期。
- 困境援助可选择原版的 50 信用点现金选项，也可继续用食物帮助她；同次援助与好感只结算一次。
- 数据盘由保管人决定谁能交出。玩家不保管时不能出售不存在的盘。
- 路线乙的保护渠道分别检查治安部/上层区声望与真实材料；条件不足会自动转成有完整内容的路线甲，不再只剩悲剧。
- 恋爱必须双方明确同意；朋友路线与“慢一点”都不会扣好感或撤销救援成果。
- 0.74起，事业成立后提供按游戏日累计、由埃莉诺来访结算的合作分红；筹备期普通买卖和合作分红分别记账。

## 旧存档

已使用本 MOD 的存档会在游戏完成读取后恢复埃莉诺剧情。若剧情数据版本不兼容，本 MOD 会保留原有数据并暂停这条剧情，可换回兼容版本继续。

为了不破坏已经推进到中后期的原版 Eleanor 剧情，本 MOD 默认**不会**接管这类存档。第一次开店时会出现一个“下层区档案员”事件，询问是否重置：

- **重置**：清除原版与 MOD 的 Eleanor 剧情标记，从下一次开店/过天开始重制线。已获得的物品不会消失。
- **保留原版**：本次存档继续运行原版 Eleanor 故事，重制线不会启用。

开发调试时也可以在 F9 菜单使用“重置埃莉诺剧情线”。F9 需要游戏根目录存在 `dev.txt`。

## 构建

需要 .NET SDK 与游戏 Managed 目录中的引用程序集。

```bash
cd EleanorRomanceDev
python tools/build_content.py    # 从 Content/*.json 生成 *.g.cs 与中英 CSV
bash build.sh                    # 构建到 bin/Release，再部署到 Mods/EleanorRomance
```

`Content/story_v06.json` 与 `Content/dual_romance_v04.json` 是文本源。旧版 `tools/legacy/parse_v06.py` 会覆盖当前源，已归档且不要运行。

`build.sh` 会在覆盖安装目录前保留一份 `dist/rollback_*` 备份，并检查 DLL 与 CSV 非空。

发布前请按 [`docs/MODDING_SECURITY_COMPATIBILITY.md`](docs/MODDING_SECURITY_COMPATIBILITY.md) 核对 public/open_beta 分支，并在游戏 F8 控制台运行 `mod-scan eleanor_romance` 自查能力与 `DEPRECATED` 项。

交易与物品占格的离线回归（PowerShell 7，先完成构建）：

```powershell
pwsh -File tools/test_runtime_flows.ps1 -Managed '<游戏根目录>\Probably Stolen_Data\Managed'
pwsh -File tools/test_runtime_flows.ps1 -Managed '<游戏根目录>\Probably Stolen_Data\Managed' -Maid
```

测试在内存中替换渲染、本地化等边界，保留原生交易完成判断、对话衔接和占格碰撞检查；覆盖 13 个交易章节的自动/手动收尾、溢价好感和手镯旧占格迁移。不会修改游戏文件或存档，实机交互仍需验收。

### 维护规则

- 文本源是 `Content/*.json`；修改后运行 `python tools/build_content.py` 与 `python tools/check_project.py`。
- 改剧情、选项、日期、路线或结局时，必须同步更新 `docs/route_map.html` 与 `docs/ROUTE_MAP_MAINTENANCE.md`，并运行 `python tools/check_route_map.py`。
- 不运行 `tools/legacy/parse_v06.py`；它会用旧台本覆盖当前内容源。
- 未经明确要求，不推送 GitHub、Steam 工坊或 Nexus。
