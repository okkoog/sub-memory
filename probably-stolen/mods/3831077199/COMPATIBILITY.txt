0. 一句话总结 / Summary
--------------------------------------------------------------------------------

本模组只在「玩家站在杰克逊博士店里」并且「他的上货流程正在跑」时接管柜台。
其它任何场景（玩家自己的店、串门联机、别的商人、白天）完全不介入。

This mod only takes over the counter while the player is inside Dr. Jackson's shop
AND his stocking routine is running. In every other situation (the player's own
store, multiplayer sessions, other merchants, daytime) it does nothing.

如果你的货在博士店里没出现、被误判、或被销毁，看第 3、4 节。
If your goods do not appear in his shop, get misjudged or get destroyed, read
sections 3 and 4.

1. 本模组会接管什么 / What this mod takes over
--------------------------------------------------------------------------------

接管动作只有两个，都在杰克逊博士店里生效：
Exactly two things are intercepted, and only inside his shop:

  (1) PlayerStore.TryAddDirectSellingItemToTable
      两个重载都会被前缀拦截 / both overloads are prefixed:
          TryAddDirectSellingItemToTable(GameItem item, bool, bool, bool, int)
          TryAddDirectSellingItemToTable(string id,  bool, bool, bool, int)
      被接住的物品不会走原版摆放，而是进入本模组的分页列表。
      Captured items skip the vanilla placement and enter this mod's page list.

  (2) RNG.Roll 三个重载（仅当玩家开启了「生成率 100%」）
      RNG.Roll, all three overloads (only when the player enabled 100% generation)
          Roll(int)  /  Roll(float)  /  Roll(int,int)
      只在博士店的上货窗口内强制返回 true，别处完全不干预。
      Forced to true only inside his stocking window; nothing else is touched.

除此之外不碰任何游戏方法 / Nothing else is patched:

  - 不改 DrJacksonLocation.Leave 的方法体（只读日志 + 异常兜底）
    DrJacksonLocation.Leave body is never modified (read-only log + finalizer)
  - 不改 ClearFrontInv / ClearBackInv / TransferCounterToBackInv / EmporiumTryAdd
    those four are untouched
  - 不移动玩家已购买的物品
    player-owned items are never moved
  - 不联网、不写存档、不声明任何能力（Capabilities 为空）
    no network, no save writes, no declared capabilities (Capabilities is empty)

2. 你的模组应该怎么放货（推荐做法）
   How to offer your goods (recommended)
--------------------------------------------------------------------------------

【推荐】照原样调用上货接口，不需要为本模组做任何特殊处理：
[Recommended] Call the stocking API as usual; no special handling is needed:

    PlayerStore.Instance.TryAddDirectSellingItemToTable(
        myItem,           // GameItem
        false,            // isOwn        - shop stock is always false
        false,            // ignorePerk
        false,
        0);               // forcedHeat

本模组会在博士店里接住它、分页摆放、并且：
Inside his shop this mod captures it, pages it, and then:

  OK  返回 true —— 你不需要处理「放不下」
      returns true - you never have to handle "does not fit"
  OK  物品会真实归属到前台柜台（parentInventory == frontInv）
      the item is genuinely parented to the front counter
  OK  上货窗口结束后统一分页，物品不会消失
      pages are built after the window closes; the item does not vanish

【重要】请务必检查返回值 / [Important] always check the return value:

    bool ok = PlayerStore.Instance.TryAddDirectSellingItemToTable(item, ...);
    if (!ok) { /* 真的放不下，可以自行销毁或丢弃 */ }
             /* really does not fit - you may destroy or discard it */

本模组接住你的物品时会返回 true，所以你的「放不下就销毁」分支不会误触发。
This mod returns true when it captures your item, so your "destroy on failure"
branch never fires by mistake.

3. 常见问题与结论 / FAQ
--------------------------------------------------------------------------------

Q1: 我的物品在博士店里消失了。
    My item disappears inside his shop.
A1: 先确认你的调用发生在「博士店上货流程内」。
    First check that your call happens inside his stocking routine.
    本模组只在上货窗口开启时接货。窗口之外的调用会走原版流程，
    而原版在柜台满时会把物品销毁（GraphUtils.TryAcceptAllOrDestroy）。
    This mod only captures inside the stocking window. Calls outside it take the
    vanilla path, and vanilla destroys the item when the counter is full.
    如果你的物品很重要，请检查返回值并自行保留。
    If the item matters, check the return value and keep it yourself.

Q2: 我检查了 parentInventory，发现它是 null / 不是柜台。
    I checked parentInventory: it is null / not the counter.
A2: 本模组接住物品后会立刻把它停回柜台（UncheckedAccept），
    所以 parentInventory 应该是 frontInvinvElement。
    This mod parks the item back on the counter right after capturing, so
    parentInventory should be frontInvinvElement.
    如果你在「同一帧内、本模组处理之前」检查，可能读到 null。
    Reading it in the same frame, before this mod runs, may still show null.
    建议：延后一帧再检查，或直接信任返回值。
    Recommendation: check a frame later, or just trust the return value.

Q3: 我的模组会读取柜台内容做判断，翻页时看到的内容会变。
    My mod reads the counter contents; they change when pages flip.
A3: 这是设计使然。本模组一次只摆一页。
    That is by design - only one page is laid out at a time.
    如果你的逻辑依赖「柜台上所有货」，请改用官方的完整货单钩子：
    If your logic needs the complete list, use the official hook instead:
        ModHook.OnPlaceInventorInventoryItemEarly += (List<GameItem> items) => { };
    这个钩子在物品被摆放之前触发，拿到的是完整列表。
    It fires before placement and hands you the full list.

Q4: 我在别的商店/玩家自己的店里也看到分页栏。
    I see the page bar in another shop / the player's own store.
A4: 不该发生。请把日志发给我们。
    That must not happen - please send us the log.
    正常行为是：只有 CurrentLocationId() == "dr_jackson" 时才有分页栏。
    Expected: the bar exists only when CurrentLocationId() == "dr_jackson".

Q5: 联机（深空串门）时我的货被分页了，客户端不同步。
    In multiplayer my goods got paged and clients desync.
A5: 本模组检测到「深空串门 / Probably Multiplayer」模组
    （ID: lemocuber_probablymultiplayer）时会自动降级：不接管网络来的库存。
    This mod detects Probably Multiplayer (ID lemocuber_probablymultiplayer) and
    degrades automatically: it does not take over networked stock.
    如果你自己的模组也在联机时同步商店，请同样做这个判断。
    If your mod syncs shops too, make the same check.
