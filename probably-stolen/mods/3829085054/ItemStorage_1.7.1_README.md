# 堆叠收纳（ItemStorage）

这个 MOD 给游戏加了一种储物：收纳箱，如果有想添加的内容&遇到了BUG可以直接@浮生若梦，看到了就会回复，长时间没回复可能是睡着了。

## 遇到问题想让我查

把 Player.log 整个文件发给我就行——截图和文字描述看不出问题在哪，日志才能定位。

1. 游戏里打开 设置 → 模组 → 堆叠收纳，把「输出调试日志」打开，再点面板底部的「应用」；只拨开关不点应用是不生效的。
2. 把问题复现一次，退出游戏后马上复制日志——游戏每次启动都会把上一份覆盖掉。
3. 日志在这里（把这行粘进资源管理器地址栏）：
   `%USERPROFILE%\AppData\LocalLow\Questing Goose Studio\Probably Stolen\`
   文件名叫 `Player.log`；如果已经重启过游戏，`Player-prev.log` 是上一次的。
4. 顺手说一下装了哪些 MOD（工坊订阅列表截图就行），还有出问题前做了什么。

用 AI 帮忙排查的话，把这份 Player.log 全文一起交给它：日志里以「堆叠收纳」开头的行是这个 MOD 的输出，模组 ID 是 `Dream_Item_Storage`，版本号看开头那行。

## 玩法说明

**获取**：安装 MOD 后第一次进店铺，自动获得第一个收纳箱（带【破旧】标签，卖价约 150）。之后杰克逊博士上门时，会售卖收纳箱。

- 该收纳箱占用内存少，如有因为收纳箱出现卡顿，请联系浮生若梦修复卡顿。
- 物品属性：2×3 占格，价值 600，储藏（STORAGE）类型。
- 存放方式：把物品拖到收纳箱上松手，按自动顺序进入格子；把物品拖到详情面板的某个格子上松手，直接进对应格；点击一键收纳，一键把店里主界面空间（橱窗、垃圾桶、其余所有储物容器内、海报后除外）里与盒内已有种类相同的物品收进盒子。
- 在外出的地面上（拾荒场）也能点一键收纳、按快捷键收走地面上的同类物品，箱子要带在身边；全箱收纳仍然只能在店内使用，店外按会提示回店。
- 每页的格子数在 设置 → 模组 → 堆叠收纳 的「槽位数量」里切，分 16 格和 25 格。25 格是把 1-16 格按 5 列重新排成 1-25 格，序号还是连着的，不会在右边和下边补格；窗口会宽一些，底下四个按钮也改成左右各两个。从 25 格切回 16 格时，超出的格子先冻结，物品不会丢，切回 25 格就原位恢复。
- 收纳箱可以用「储藏区扩建套件」扩页，单箱最多 5 页。窗口上方会出现一排页签，点一下切页；双击页签能改名，改的名字会跟着存档保存。总容量 = 每页格数 × 页数：25 格档 5 页就是 125 格，16 格档 5 页是 80 格。
- 齿轮面板里有三个「可吸纳」开关：储藏区、机器区、走私格（各自的扩建版本也算进去）。打开之后，一键收纳和全箱收纳会去这些区里取箱内已有的同类物品；三个开关都是关着的初始状态，开一次就对所有收纳箱生效。机器区里摆着的机器本身不会被收走，只有玩家丢进去的散件会。装了「更好的储藏区」的话，它建出来的分类页也归「可吸纳储藏区」管。这几个开关换存档也保留。
- 齿轮面板第二页「收纳规则」里的「配对容器」：点它，再点要配对的容器（冰箱、储物箱、机器都行）——配的是这一类容器，店里所有同款都会成为一键收纳的来源，之后新买、刚捡到的同款也算。清单全店共用一份、跨存档保留：任意一个箱子配好，其他箱子的一键收纳同样生效，开新档也还在，最多 10 类。配完自动退出，想再配就再点一次。一键收纳和全箱收纳会收走这些容器里与箱内同款的物品，机器的输入区不动。只能在店里配对。
- 「排除容器」：同一类里只想留几台不收时用。点「排除容器」，再点那一台容器，就只把这一台从一键收纳里剔除，同款其他台照收。全店共用一份排除名单，最多 10 台；被排除的容器上锁、卖掉都不影响名单本身。排除后自动退出，想再排一台就再点一次。只能在店里排除。这份名单只在当前存档生效，换到别的存档是空的，切回原来的存档原样还在。
- 「配对容器清单」按类列出全店共用的配对，并显示该类现在店里能收几台、其中几台已排除；点一条取消这一类（所有箱子一起停收），底部能一次全部取消配对。
- 「排除容器清单」按台列出被排除的容器，点一行恢复这一台，底部能一次全部取消排除。这份名单只在当前存档生效。
- 「拒收物品」：同一种物品不想被一键收纳带走时用。点「拒收物品」，再点那种物品，之后一键收纳、全箱收纳、配对容器里都不会再收它；想存的时候把物品拖到具体格子上松手，照样能存。全店共用一份拒收清单，最多 10 种，换存档也保留。箱子本体、展示柜里的陈列品、不是你自己的东西不能拒收。
- 「拒收物品清单」按种列出被拒收的物品，点一行取消这一种，底部能一次全部取消。
- 「固定物品」：游戏里右键物品选「固定」，这件东西就不会被一键收纳、全箱收纳、配对容器收走，拖到箱子上松手也不会进箱；想存的时候把物品拖到具体格子上松手，照样能存。固定是游戏自带的功能，在右键菜单里取消固定就恢复正常。固定记在这一件东西上，同款的其它件不受影响。
- **调整物品位置**：箱子标题栏齿轮左边有个按钮，点一下进入调整模式。点一格选中，再点另一格放下：那格空着就整格搬过去，是同款就并进那一格（装不下的留在原格），是别的东西就两格对调。再点同一格取消选择，再点按钮或关掉窗口退出。锁定的格子也能搬，锁跟着内容一起走。两格水的配比不同时会先提示一次，再点同一格才混合，混合后不能还原。
- 三张清单都只在店内能打开。储藏区、机器区、走私格用上面那三个开关控制，不参与配对、排除和拒收。
- 已经存入的物品取出时再次获得，像背包、水瓶打印机这类内部装着东西的物品存不进去，请清空其中的物品后再放入。
- 同类物品优先堆进已有的格子，那格满了会开新格。每格默认最多 99 个，设置面板里能改（20-999）；改小只拦新放进去的，不会削减已经存好的。
- 从别的箱子归拢同类时，会先把箱里所有同类未满的格子挨个补满，剩下实在放不下的才另开新格。齿轮面板的「至少留一件」对归拢同样生效：开着时源格留 1 件不搬，关掉时整格搬空。
- 同类物品堆在同一格时只记一份属性 + 每件一个编号，所以一格堆到 999 件同款也撑不大存档；真正占体积的是每件都不一样的物品（动物最典型）。
- 左键点格子取出 1 件，右键点格子一次取 5 件，格子里不够 5 件会全部取出，空间不够时停止取出。
- 格子里存的是"这一类东西"，耐久、电量、剩余次数、水量这些属性是整格合在一起的：存 10 个半耐久的东西，取出来就是按格里的总耐久分配。默认先出满的，想让用完的先出来，去齿轮面板的「倒序取出」把对应的开关打开就行——开了之后手动点格子先给已用尽的，满的留到后面，总量一样不多不少。一键上货、全箱上货不看这个开关，照样先出满的。
- **动物默认放不进箱子**：老鼠、鱼（活的死的都算）、鱼苗、受精鱼卵都会被拒，提示「动物不能存进收纳箱（可在模组设置中允许）」。鱼肉、鱼片、没受精的鱼卵属于食材，照常能存。箱里原有的动物随时能取出，不受这个限制影响。
- 要让动物进箱子，去 设置 → 模组 → 堆叠收纳 打开「允许存放动物」。打开后注意存档体积：每只动物的年龄、体重、基因、饥饿都是单独一份数据，没法像普通物品那样合并，一只约 3.6 KB。十箱塞满（10 箱 × 125 格 × 999 只）约占 4.2 GB 存档，会非常非常卡；正常游玩建议全档别超过 200 只（约 0.7 MB）。能存的时候，取出顺序是后存入的先取出，格子贴图显示最新存入的那只。
- 不管「允许存放动物」开没开，一键收纳的箱间归拢和箱间合并都不会动动物格：别的箱子里的老鼠、鱼不会自己搬过来，两格同种动物也不会自动并格，要动只能手动拖。
- 物品会按真实品质分格堆放：纯度不同的分开；带真假的东西按真假分（同真值放一格，标签名字怎么写不影响），取出来的时候标签会恢复成真实状态。
- 无法放入的物品：【储藏】、【机器】、酿造中的酒瓶、【赃物】、【模组】、【物资箱】、【节点】、【工具箱】、动物（老鼠、鱼、鱼苗、受精鱼卵，默认不放行，设置里可允许），还有显示成问号的物品（见下面「其他 MOD 的物品」）。

**一键上货**：收纳箱窗口底下一排现在有四个按钮，从左到右是「全箱收纳」「全箱上货」「一键上货」「一键收纳」；25 格时这四个按钮分列左右两侧，中间空一格。

- 一键上货是把**这个箱子**里的东西摆上柜台卖，全箱上货是把**你所有收纳箱**里的东西摆上柜台。两个都只会在有顾客站在店里时工作。
- 上货只挑顾客想买的东西：他喜欢的类型才会被摆上去，不感兴趣的、以及官方规定不能卖给这位顾客的（比如警察不收违禁品）都会自动跳过。"又卖又收"的混合型顾客（化学家、矿工、拾荒者这些）同样支持——他自己带来的货摆在进货区，想收的东西从收纳箱上柜台，两边互不打扰。买水的顾客按水质档次挑货：清单里要哪几档就只上哪几档，同档里纯度最高的格优先。
- 摆上去的每件东西都按官方实时计价卡着顾客的预算，预算花光或柜台摆满就停。多样性的顾客（每样只买一件那种）每样只摆一件，不会把柜台摆满卖不掉的死货。
- 空桶、空电池这类"有容量却空着"的物件不自动上货——卖出价太低，留着等你装满再卖。
- 左键点格子下面的名字条可以锁格：锁住的格子不上货，图标左上角有官方"固定"同款小锁标记，悬停也有说明。格子清空或换物自动解锁。想整箱不参与全箱上货，去齿轮面板开"不参与全箱上货"——注意这个开关只影响全箱上货，箱子自己的一键上货照常能用。
- 四个快捷键都在齿轮面板里绑：一键收纳 / 一键上货是每个箱子各自的键，全箱收纳 / 全箱上货是全局共用一个键。绑定前会自动检查冲突，撞了官方按键或其他箱的键会拒绝并提示。

## 其他 MOD 作者看这里

收纳箱的存入=销毁物品本体、取出=重建物品实例（数据全部记在箱子标签上，省内存）。从 v1.2.0 起，**有独立状态的物品取出时会写回原 uniqueId**，按 uniqueId 记账的 MOD 取出后能直接对上账。

从 v1.5.0 起，`GetSlotCount(box)` 返回这个箱子**当前可见槽总数** = 每页格数（16 或 25）× 页数（1-5，随扩页变化），最大 125。请一律以它为准，不要假定固定格数。超出可见范围的槽号对接口完全不可见：`GetSlotInfo` 返回 null、`TryWithdraw` 拒绝、`TryDeposit` 把它当成"没有偏好"落到可见格里。直接读 `ITEM_STORAGE_SLOT_*` 标签的代码不受支持。

如果你的保存前校验需要处理"账本里的物品暂时不在场"，可以查收纳箱的公开桥（modId `Dream_Item_Storage`，类型全名 `ItemStorage.ItemStorageApi`，纯 public static，DLL 反编译或 README 即可发现全部接口），把这种情况降级成"寄存中、允许保存"：

```csharp
// 反射探测（类型不存在时静默跳过，不产生硬依赖）：
var asm = System.AppDomain.CurrentDomain.GetAssemblies()
    .FirstOrDefault(a => a.GetName().Name == "ItemStorage");
var api = asm?.GetType("ItemStorage.ItemStorageApi");   // 注意：命名空间就是 ItemStorage

// static bool IsUidStored(int uid)
//   → 该 uniqueId 是否正寄存在玩家任一收纳箱中（版本化缓存，O(1)）
// static IReadOnlyList<int> GetStoredUids(GameItem box)
//   → 指定收纳箱（全部格子）内寄存的 uniqueId 并集
// static IReadOnlyList<int> GetSlotUids(GameItem box, int slot)
//   → 指定收纳箱指定格子的 uniqueId 列表
// static IReadOnlyList<int> GetAllStoredUids()
//   → 全部收纳箱寄存编号并集快照（批量对账推荐：一次拿全表自己建 HashSet）
var isStored = (bool?)api?.GetMethod("IsUidStored",
    System.Reflection.BindingFlags.Public | System.Reflection.BindingFlags.Static)
    ?.Invoke(null, new object[] { item.uniqueId });
```

语义约定：`IsUidStored` 返回 true = 物品本体已销毁、数据完整寄存在收纳箱里，取出时会原样写回这个 uniqueId——你可以放心把"实物失踪"挂起而不是阻止保存。存箱期间账本暂时对不上是设计内窗口期，不是数据损坏。有问题随时群里@浮生若梦。

**使用约定（写给所有调用方）**：

1. `IsUidStored`/`GetAllStoredUids` 走版本化缓存，随意调用不伤性能；但请**不要在每帧 Update 里轮询**——按事件（保存前校验、物品变动）调用即可，这是对玩家机器的基本礼貌；
2. 取出接口（`TryWithdraw`）请提供**玩家可见的入口**（按钮/确认），勿在后台静默扫箱搬货——箱子东西不告而取，玩家第一个找的是收纳箱作者；
3. 接口异常会打 `[堆叠收纳API]` 前缀日志，对接调试时 grep 这个前缀。

**需要公开接口，直接找我，不用绕。**

如果你的 MOD 需要读收纳箱的数据、想在收纳时做判断、或者要避开某个行为，先别急着 Harmony patch 内部方法。内部方法没有兼容承诺——改名、改签名、改调用顺序都是随时可能的事。更麻烦的是它往往不报错：补丁找不到目标就静默跳过，玩家那边只看到「某个功能突然不工作了」，维护起来对双方都麻烦。

需要什么，到堆叠收纳 MOD 的创意工坊讨论区留言说清楚用途就好，欢迎联系。公开出去的接口方法名与签名我会当契约维护，重构也不会坑到你。

已经在 patch 的也没关系，说一声，我们把它换成正式接口。
